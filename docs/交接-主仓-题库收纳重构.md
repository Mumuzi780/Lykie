# 交接规格：题库收纳重构（从零设计版）

> 交接对象：主仓代码智能体。本文档为定稿规格，按此执行，不参考旧 folders 实现的交互。
> 制定日期：2026-10-11。作者：LiZF（已拍板）。

## 0. 背景与目标

现有题库侧栏文件夹功能"手感不好"：移动靠弹窗太繁琐、文件夹信息密度低、
"长期不刷的题放起来"的初衷没有系统支撑。

本次重构的核心思想：**位置与状态分离**。

- `folder_id` 管位置（在哪个文件夹）
- `archived` 管状态（是否归档，独立于文件夹）
- `last_studied_at` 是系统自动记录的时间信息（用户零操作）

归档不是文件夹，是另一个抽屉。归档的题库从主列表彻底消失，
保留 folder_id，恢复时回到原位置。

## 1. 数据结构

### 1.1 bank 对象新增字段（bank.json 里每个题库）

```json
{
  "archived": false,
  "last_studied_at": "2026-10-11 12:13"
}
```

- `archived`：bool。缺省 false。**读取时用 `b.get("archived")` 即可，
  不写迁移脚本**——旧数据没有此字段等同于 false。
- `last_studied_at`：字符串 "YYYY-MM-DD HH:MM"。缺省空串。
  由系统在两个时机写入（见 3.3），用户不可编辑。
- `folder_id`：语义不变，但归档不再清空它。

### 1.2 store.folders 不变

文件夹自身结构不动（id/name/created_at），list_folders 的返回扩展见 3.2。

## 2. 侧栏结构（重写 renderBankList）

```text
▸ 置顶区（手动拖拽排序，永远显示）
  └ 未归档且 folder_id=null 的题库
▸ 文件夹区（每个文件夹是可折叠块）
  └ 📁 名字 （N 个题库 · 最近 X 天前）
      └ 内部题库（nested 样式）
▸ 单独题库区 = 置顶区（同一区，不单独分）
────────────
▸ 🗄 归档 (N)      ← 特殊抽屉，默认折叠
▸ 模考 / 错题集   ← mock.js appendCollections 挂载点，保持不变
```

渲染规则：

1. 主列表只显示 `!archived` 的题库。
   - `folder_id=null`（或指向已删文件夹）→ 根区条目
   - 有 folder_id → 归入对应文件夹块
2. **归档抽屉**固定渲染在最底部（模考区之上）：
   - 头部显示 `🗄 归档 (N)`，N=归档数；N=0 时整个抽屉隐藏
   - 默认折叠，点击头部展开/收起；折叠状态存 localStorage
     （key: `lykieArchiveCollapsed`，默认 true）
   - 展开后列出全部 archived 题库，条目用现有 bank-item 样式 +
     `bank-item-archived` 附加类（整体降饱和/半透明）
3. 归档条目的操作按钮只有两个：**恢复**、**删除**（查看/分享/重命名/移入都不显示；
   分享需求极低，砍掉；查看保留会破坏"收起来"的心理感受，也砍）。
4. 文件夹头部新增 meta 灰字：`N 个题库 · 最近 X 天前`。
   X = 内部题库 last_studied_at 的最大值距今天数；
   内部全部为空则只显示 `N 个题库`。
5. 题库条目 meta 行：原 imported_at 保留，
   追加灰字 `· X 天前`（last_studied_at 距今天数；为空则不追加）。
   天数 <1 显示 `今天`，1-2 天显示 `昨天`/`前天`，>60 显示 `60+天前`。

## 3. 后端 API

### 3.1 修改 /api/banks 返回（app.py api_banks）

bank 条目增加两个键：

```python
"archived": b.get("archived", False),
"last_studied_at": b.get("last_studied_at", ""),
```

folders 键的每项增加：

```python
"last_used": "2026-10-11 12:13"   # 内部题库最大值，无则 ""
```

前端拿原始时间自己算天数文案，后端不算相对时间。

### 3.2 新端点

```python
POST /api/banks/archive      {"id": "..."}            → archived=True
POST /api/banks/unarchive    {"id": "..."}            → archived=False
```

- 都校验题库存在；都返回 `{"ok": True, "banks 已由前端刷新"}`
  （按现有 jsonify_user 风格，带上完整 banks/folders payload，
  前端 renderBankList 直接复用，见下）。
- **归档不清 folder_id、不动 current_bank_id**。
  若归档的是当前选中题库，前端在响应后清空选中态并回根视图
  （前端处理，后端不管）。
- 实现放 `lykie/folders.py`（模块语义改为"题库收纳"），
  新增 `archive_bank(store, bank_id)` / `unarchive_bank(store, bank_id)`，
  ensure_folders 的孤儿 folder_id 清理逻辑保持不变。

### 3.3 last_studied_at 埋点（仅两处，别多埋）

1. `POST /api/select_bank`（app.py api_select_bank）：
   选中题库成功时写 `b["last_studied_at"] = now_str()`。
2. 刷题提交路径：找到斩题状态变更的保存点（/api/answer 或等价端点，
   代码里搜 `status.*killed` 的赋值处），每次正确作答/斩题落库时更新同字段。
   **只在"学习行为"时更新，导入/重命名/分享不更新。**

时间格式统一用 folders.now_str()（"YYYY-MM-DD HH:MM"）。

### 3.4 既有 /api/banks/move 语义收紧

- 移动 archived=true 的题库：返回错误 `"先恢复再移动"`（防误操作）。
- 其余不变（move 时 folder_id 有效性校验已有）。

## 4. 前端交互（script.js）

### 4.1 拖拽（核心提速）

数据流统一：dragstart 时 setData('application/x-lykie-bank', bankId) 或
'text/plain' 加前缀 `bank:<id>`（与文件夹拖拽区分）。

| 拖拽源 | 放置目标 | 动作 |
|---|---|---|
| 题库条目（未归档） | 文件夹头部 | move 到该文件夹 |
| 题库条目（未归档） | 根区空白处 | move 到根（folder_id=null） |
| 题库条目（未归档） | 归档抽屉头部 | archive |
| 归档条目 | 根区/文件夹头部 | unarchive + move 一步到位 |
| 文件夹头部 | 其他文件夹头部 | 现有排序逻辑不变 |

细节：

- 拖拽悬停时文件夹头部加类 `drop-hover`（高亮边框，css 已有类似
  drag-over 类，可复用改名）；
- **拖拽进行中归档抽屉自动展开**（dragenter 时清 collapsed），
  拖拽结束若抽屉内为空则自动收起；
- 拖拽期间 body 加类 `is-bank-dragging`，防止文本误选中。

### 4.2 归档入口

1. 未归档题库条目的操作按钮区：把现有 5 个按钮精简为
   **查看 / 归档 / ⋯**（⋯ 展开二级菜单：分享、移入、重命名、删除）。
   常驻按钮从 5 减到 3。
2. "移入"弹窗保留（移动端兜底），但归档不进这个弹窗——
   归档是状态切换，不是移动，独立按钮。

### 4.3 归档抽屉交互

- 恢复按钮 → POST unarchive → 刷新；恢复的目标位置 = 原.folder_id
  （可能已经不存在，ensure_folders 会兜底回根）。
- 归档抽屉内条目不参与拖拽排序，只支持拖出到主区（恢复+移动）。

### 4.4 缓存与刷新

- foldersCache 结构扩展（每项多 last_used），renderBankList 全量重渲染，
  不做局部更新（现有实现就是全量，保持）。
- archive/unarchive 响应里带完整 banks/folders，前端直接
  用响应体替换缓存后 renderBankList()，少一次 /api/banks 往返。

## 5. 明确不做（本次边界）

- 不做自动归档（N 天未刷自动移）——误伤率高，判断留给用户
- 不做按最近使用自动排序——位置不稳定伤位置记忆
- 不做文件夹嵌套
- 不做标签系统
- 不做批量归档（以后有需要再加）
- 模考 collections / 错题集 wrong_sets 的渲染与数据完全不动
