# 交接规格：对话标注通道（//）与轮次留痕

> 定稿日期：2026-10-31。作者已拍板全部决策点，本规格可直接执行。
> 纪律说明：本规格**不改动对话管道行为**（prompt 组装、模型调用、记忆读写全部原样），只做旁路留痕与新递交通道，符合「白模验证期代码冻结、修正走内容层」的既定纪律。

## 一、背景与目标

作者（用户）在与 Lykie 聊天时负责判断「她该怎么说、怎么更像人」，顾问负责归因「她为什么这么说」。此前缺一条递交通道：

- 她回复不合理时，作者知道该怎么改，但没有办法定位当时的聊天环境（她当时看到了什么 prompt）；
- 想当场提意见，只能用旧「记」按钮人工圈范围、写备注，用着不顺手；
- 👍👎 点赞点踩与作者实际工作流不匹配，且 corrections 注入早已在白模重构中废弃，按钮成了僵尸入口。

目标：**作者在聊天输入框直接写 `//` 开头的反馈 → 拦截不发给模型 → 自动锚定最近一轮回复并固化该轮完整 prompt 快照 → 进入作者收件箱（分析队列）**。作者全程零成本复原环境，顾问拿到全现场归因。

## 二、拍板记录（2026-10-31）

1. 反馈唯一通道 = 聊天输入 `//` 前缀；👍👎记 三个气泡按钮**全部下线**。
2. 好评标记：`//好`（「好」后紧跟空白、标点或结束即为好评，否则按普通反馈）。
3. 反馈递交后她不知情：不进模型、不进 chat_tail；面板显示特殊样式气泡（含「已递交作者」角标），刷新后仍在。
4. 锚定规则：`//` 反馈自动锚定**最近一轮 assistant 回复**，固化该轮完整 messages 快照。
5. 收件箱：极简列表页，状态 待分析 / 已采纳 / 已忽略，仅作者（LiZF）可见。
6. QQ 网关本期不动（`/v1/chat/completions` 行为零变化）。
7. 「纠正：」前缀的当场纠正模式**保留**（它由输入框前缀触发，与点踩弹窗无关，见 app.py:3340）。
8. 旧作者日志（记）后端路由与历史数据保留存档，仅下线前端入口；旧 corrections 数据保留不再新增。

## 三、总体设计

```
作者聊天 → 正常消息走原管道 ──→ 模型回复
                │
                └─ 每轮调用后旁路存快照 → data/users/<名>/lykie_turns/（滚动 50 轮）

作者输入 // 反馈 → 前端拦截（不进连发队列）→ POST /api/lykie/annotate
                → 后端取最近快照固化进 data/lykie_annotations.json（上限 200 条）
                → 面板出 note 气泡（她不知情）

作者/顾问 → /annotations 收件箱 → 看列表/回放快照/改状态
```

## 四、详细规格

### 4.1 轮次留痕（快照底座）

**新模块 `lykie/annotations.py`**，职责：快照存取、`//` 解析、标注库读写。

**`lykie/converse.py` 改动（唯一管道改动，零行为变化）：**
- `handle_message` 返回 dict 增加 `"messages"` 键 = 发给 `chat_completion` 的完整 messages 列表（即 build_messages 的产物）。其余键不变。
- 调用方 `app.py:3412` 与 `lykie/qq_gateway.py:78` 中，网关不读新键，行为不变。

**`app.py` 的 `api_lykie_chat` 改动：**
- 模型调用成功后（3419 行拿到 result 之后、写对话历史前后均可）调用 `lykie_annotations.save_turn(...)` 存快照。
- 错字折合早退分支（typo_fix，3364-3377）不产生快照（没有模型轮次）。
- 纠正模式（correct）也存快照（meta 里 mode 标 correct）。

**快照文件：`data/users/<名>/lykie_turns/<ts>_<4位随机hex>.json`**

```json
{
  "id": "1762..._a3f1",
  "ts": 1762...,
  "account": "LiZF",
  "mode": "chat",
  "stage": "casual",
  "model": "deepseek-chat",
  "temperature": 0.8,
  "question_card": null,
  "messages": [ {完整发给模型的 messages，一字不改} ],
  "reply": "她这轮的原话",
  "silent": false
}
```

- `messages` 必须与实际传给 `chat_completion` 的对象**完全一致**（同一引用序列化），禁止重组。
- model 取 `lykie_llm.get_config()["model"]`；stage 取当时 state 的感情层。
- 滚动窗口：保留最近 **50** 个，超出删最旧（按文件名排序即时间序）。
- `lykie/accounts.py` 新增路径助手：`lykie_turns_dir(username)`、`lykie_annotations_path()`（风格对齐既有 `lykie_author_log_path`）。

**清空联动：** `/api/lykie/chat_reset_opening`（清到开场后）与 `/api/lykie/memory_clear`（清空记忆）两个路由在现有逻辑后**清空本账号 lykie_turns 目录**——新会话新留痕，避免 `//` 锚到重置前的旧轮次。

### 4.2 `//` 反馈捕获

**判定规则（前后端同一份，后端为准）：**
- 消息 `lstrip()` 后以 `//` 开头 → 是反馈；否则正常聊天。行中/行首非开头的 `//` 不拦。
- 去掉 `//` 后为空（且不是 `//好`）→ 返回错误「反馈内容为空」，消息不消费、不进模型。
- 好评判定：剩余正文以 `好` 开头，且 `好` 之后是结束/空白/标点（`，。！？：；、 ` 等）→ `vibe: "up"`，正文取其余部分（可为空）；否则 `vibe: "down"`，正文原样。
  - `//好` → up，无描述
  - `//好，短句分条很自然` → up + 描述
  - `//好烦` → down，正文「好烦」（刻意不误判为好评）
  - `//她只是被打招呼就交代家底，理想回复：你好，我叫Lykie` → down + 描述

**前端 `static/script.js`：**
- `onLykieSend` 入口处（进 chatBatchQueue 之前）判定：是反馈则**不进连发队列、不触发队列冲刷、不受 lykieBusy 限制**，独立走 `submitLykieNote(text)`。
- `submitLykieNote`：先出 note 气泡（见下），`POST /api/lykie/annotate`，失败时追加 system 错误气泡。
- note 气泡样式：用户消息位置、灰色虚线边框、角标「已递交作者·她不会看到」；`appendLykieBubble` 加 `opts.note` 支持（`dataset.note = '1'` + class）。
- 持久化：`serializePanelLog` 透传 `note: true`（对齐现有 silence 的处理方式）；恢复渲染时带同样式。
- 输入框 placeholder 追加一句提示 `// 开头 = 反馈直达作者`。

**新路由 `POST /api/lykie/annotate`（app.py）：**
- 入参：`{ text, panel_messages? }`（text 为含 `//` 的原文）。
- 逻辑：后端复判 `//` 前缀 → 解析 vibe/正文 → 读本账号 lykie_turns 最新快照 → 无快照返回 400「本账号还没有对话留痕，无从标注」→ 快照**拷贝**固化进标注条目 → 写入全局标注库 → 若带 panel_messages 则 `lykie_memory.set_panel_log` 持久化面板。
- 纯本地操作，**零模型调用**。
- 出参：`{ ok, id, vibe, anchor: { ts, reply_preview } }`（reply_preview 取快照 reply 前 120 字，供前端确认锚对了）。

**标注条目（`data/lykie_annotations.json`，全局单文件，风格对齐 author_log）：**

```json
{
  "id": "<12位hex>",
  "ts": 1762...,
  "time": "2026-10-31 21:04",
  "account": "LiZF",
  "vibe": "down",
  "text": "她只是被打招呼就交代家底，理想回复：你好，我叫Lykie",
  "raw": "//她只是被打招呼就交代家底，理想回复：你好，我叫Lykie",
  "turn": { ...整份快照拷贝... },
  "status": "pending",
  "status_ts": 1762...
}
```

- 上限 **200** 条，超出丢最旧。status ∈ `pending / adopted / ignored`。
- `lykie/memory.py` 的 `set_panel_log` 增加 `note` 标志透传（一行改动，与 silence/no_feedback 同款）。

### 4.3 收件箱（/annotations）

**页面路由 `GET /annotations`（app.py）：** 作者门禁复用 `_require_author()`（非 LiZF 一律 404，与 Atlas 同款）。新模板 `templates/annotations.html` + 新脚本 `static/annotations.js`（v=1）。

**API（均作者门禁，非作者 404）：**
- `GET /api/lykie/annotations` → 列表（**不含 turn.messages**，只有元数据 + text + reply_preview + status，控制载荷）。
- `GET /api/lykie/annotations/<id>` → 单条完整（含 turn.messages，回放用）。
- `POST /api/lykie/annotations/<id>/status` → `{ status }` 改状态。

**页面结构（极简）：**
- 列表行：时间 · 账号 · 好/差 · 状态徽章 · 反馈文本 · 锚定回复预览；点击行展开回放。
- 回放视图：拉详情，把 system content 按 `\n\n【` 切段（身份核/当前时间/人生档案/关系/开场/事实/题目/发送格式），每段一个 `<details>` 默认折叠，点击看原文；对话历史（user/assistant turns）与「本轮用户消息 + 她的回复」默认展开。
- 状态操作：三个按钮 待分析/已采纳/已忽略，点击即改。
- 顶部小统计：总 N · 待分析 M。

**入口：** `templates/index.html` 顶栏加「标注」链接，包 `{% if username == 'LiZF' %}`（与「建号」按钮同款门禁，非作者 DOM 无痕）。

**`/api/lykie/state` 补两个计数**（2899 路由）：`annotation_total`、`annotation_pending`；前端 `refreshLykieState` 状态行（script.js:3455）追加 `· 标注 N·待 M`。

## 五、明确不做

- 不恢复 👍👎 驱动行为，不把 corrections 重新注入 prompt（白模纪律）。
- 不做标注 → prompt 自动注入；评价只进分析队列，经顾问归因 → 作者拍板 → 内容层修正。
- 不做锚定更早轮次的 UI（快照里的 chat_tail 历史天然覆盖上下文；确有需要后续再加「第 N 轮」语法）。
- QQ 网关不接留痕、不接 `//`（公开前多用户改造时一起做）。
- 不迁移/不清洗旧 author_log、corrections 数据。
