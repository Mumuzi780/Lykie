# Lykie 形象与出场原则

> 产品/角色体验备忘。记录「谁叫 Lykie、画风怎么定、什么时候出现」，避免把吉祥物和活人角色混成一团。  
> 商业定位见 [产品定位](产品定位.md)；人设与剧情节拍见 [角色与剧情构想](角色与剧情构想.md)。

最后整理：2026-09-14

---

## 结论（先记这条）

**Lykie 是活生生的人，不是每时每刻趴在题库卡片上的吉祥物。**

工具界面应少用固定立绘占位；角色存在感靠**出场时机与关系**，不靠永远贴在题目上。

---

## 两套东西，不要混名

| | 当前题卡上的卡通（暂称「探头 / 小助手」） | 预想中的 **Lykie** |
|--|--|--|
| 画风 | Q 版、偏像素 / 轻量卡通 | 更接近真人；可以是动漫风格，**绝不是**现在的 Q 版像素风 |
| 气质 | 桌宠、新手向导、系统提示 | 大学生身份的「人」；陪伴与剧情锚点 |
| 出现频率 | 可以常驻、占角落、不抢戏 | **该来才来**：聊天、剧情、点「问问」、关键节点 |
| 心理效果 | 「有个可爱助手跟着」 | 「有人在旁边 / 在找你」 |
| 命名 | 不宜继续叫 Lykie（避免抢真人立绘） | **Lykie** 专指这一角色与正式立绘 |

当前形象**不必废弃**：更适合做桌宠、新手向导、轻量 UI 提示。  
**Lykie 这个名字和真人向立绘**，留给真正要立住人设与感情的地方。

---

## 为什么题卡上不该「永远趴着」

与产品定位一致：Lykie 是绝对特色与长期资产，类比「活生生的陪伴 / 可独立成剧情体验」，不是刷题页装饰 sticker。

设定侧也是「直接砸消息、能看见当前题、用户点了才教」——她是**会出场的人**，不是**功能图标**。

一直趴在题卡上会：

1. 把她压成吉祥物，削弱「活生生」的幻觉；  
2. 在需要安静刷题的界面里抢注意力、容易烦；  
3. 用错画风时，正式立绘还没来，先把「Lykie = Q 版」记死在用户脑子里。

更合适的分工：

- **题库 / 刷题区**：干净好用；少或不要固定「人」贴在题目上。  
- **Lykie**：面板、消息、偶尔探头、主动来找你——像真人不会 24 小时坐在作业上。

---

## 正式形象方向（未出图前的约束）

- **可以是**：真人画风倾向的立绘；动漫写实 / 半写实亦可。  
- **不可以是**：当前那种 Q 版像素风作为 Lykie 本尊。  
- **未有正式立绘前**：学习区宁可只保留对话入口与文字存在感，也**好过**继续用错形象顶替 Lykie。

具体发型、服装、画师风格等仍待定；本文只锁「像人 vs 像桌宠」和「何时出现」。

---

## 出场原则（产品侧）

| 宜 | 不宜 |
|----|------|
| 聊天面板、剧情、关系节点 | 每道题卡默认趴一只「Lykie」 |
| 用户主动点「问问 Lykie」 | 用 Q 版代替正式人设对外宣传主视觉 |
| 偶发探头 / 主动找你（有节奏） | 为了「有特色」而让角色永久占 UI 焦点 |
| 向导 / 桌宠用另一套轻量形象 | 两套形象都叫 Lykie |

一句话：**工具界面少占位；角色靠出场时机和关系，不靠永远趴着。**

## 与现有实现的关系（备忘）

- 现网题卡探头、侧栏陪伴等，属于**占位实现**；后续应拆清：向导/桌宠素材 vs Lykie 本尊。  
- 版本日志里「桌宠与长线剧情」可与本文对照：桌宠可以是轻量形象线；长线剧情与立绘走 Lykie 真人向。  
- 改 UI 时先问：这个位置出现的是「助手贴纸」还是「Lykie 本人」？名字和画风跟着答案走。

细节交互方案另开文档或直接改实现；本文只锁形象与出场边界。
