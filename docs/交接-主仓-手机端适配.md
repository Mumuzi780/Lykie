# 交接规格：手机端适配（查词 + 阅读答题 + 顶栏收纳）

> 状态：已定稿（2026-11-18，含五条技术修订），交代码智能体执行。
> 方案：2026-11-18 作者拍板「方案 A：触屏适配层」——桌面交互零改动，加触屏分支。
> 修订记录（2026-11-18 二审）：①点词查词由直查改为气泡确认制 + 已入库词本地直出（修订 2026-10-18 拍板，作者已确认）；②删除自实现长按定时器，改 selectionchange 响应系统选区；③iOS 菜单压制降级为接受并存；④新增虚拟键盘 visualViewport 处理；⑤明确触屏分支不读 mouseMode。

## 一、背景与问题诊断

手机端（≤720px）当前存在三个体验问题：

1. **查词不可用**：查词入口只有双击 + 右键 + 「作答/查词」模式开关（reading.js `dblclick` L1028 起、`contextmenu` L1050 起、`mouseMode` L44/L2125 起）。触屏上双击被系统缩放手势抢占、右键不存在、模式开关藏得深；已标记词的释义靠 `.rd-mark:hover::after`（reading.css L442），触屏无 hover 完全失效。
2. **答题悬浮卡是桌面范式**：悬浮球可拖（58px 固定定位）、题目卡可拖拽可 resize（reading.css `.rd-qball` L206、`.rd-qcard` L249），卡片宽 440px 在手机上接近全屏，resize 手柄触屏抓不住，球遮挡正文。
3. **顶栏拥挤**：720px 断点下 header 一行塞了品牌 + 统计 + 十余个操作按钮（题库/资产/导入答案/模式开关/AI 出答案/重做/错题本/翻译/编辑关键词/重置/音效/账号/建号/标注/退出，index.html L41-63），首屏过密。

## 二、总原则

- **桌面零改动**：双击/右键/模式开关/悬浮球拖动/卡片 resize/位置记忆（localStorage）全部保持原行为。
- **事件分流，不做 UA 嗅探**：所有触屏分支以 `pointerType === 'touch'`（含 `'pen'`）判定；鼠标交互走原逻辑。
- **复用优先**：查词结果表单（`rd-card`）、题目卡（`rd-qcard`）、确认气泡（`rd-bubble`）的 DOM 与渲染逻辑全部复用，只做 CSS 形态适配，不写第二套。
- **省 AI 调用**：任何触发 DeepSeek 查词/翻译的动作必须用户明确确认后才发起；已入库词释义走本地 data-gloss 零调用。
- **分三步独立实现、独立验收**，每步完成后真机验证通过再进下一步。**本次执行不提交 git**（作者验收后另行安排提交）。

## 三、改动规格

### 第 1 步：查词手机化（点词气泡确认 + 选区响应 + 底部面板）

**1.1 触屏点词 → 气泡确认**（reading.js）

- 新增 touch 分支：`pointerup`（`pointerType === 'touch'`）且**无位移**（pointerdown 记录起点，位移 < 10px，防滚动误触）且**无选区**（`selection.isCollapsed`，排除长按选词场景）时：
  - 落点位于**正文阅读区**（`.reading-p`、`.rd-q-p`、`.rd-match-stem`、判分后 `.rd-opt.is-locked`）→ `wordInfoAt()` 取词：
    - 词已入库（命中 `.rd-mark-imported`）→ **直接展示 `data-gloss` 释义**（本地零调用），进底部面板（见 1.3）。
    - 新词 → **弹现有 `.rd-bubble` 气泡挂词上方**，按钮条为「查词 / 翻译」（复用 L212 `showBubble` 的按钮结构，标记按钮仅在有选区时出现，点词场景不出现）；用户点「查词」→ `runLookup('lookup', info)`，点「翻译」→ `runLookup('translate', info)`。
  - **控件区不触发**：判分前的 `.rd-opt`、`.rd-blank`、`.rd-bank-item`、所有按钮/输入框保持作答静默。现有 `closest()` 排除链（L1030/L1034/L1054）可复用。
  - 落点未取到词（词间空隙）→ 什么都不做，并 dismiss 现有气泡。
- 取舍说明：不采用「点词直查」（虽然 2026-10-18 曾拍板），因为单击是手机最高频动作、误点率高，每次误点 = 一次真实 DeepSeek 调用（BYOK 算力红线）；多一次确认点击换零误查。已入库词本地直出保证高频复看场景即点即得。

**1.2 长按选短语 → 选区响应**（reading.js）

- **不自实现长按检测**（不写定时器）：系统长按自己会选中词/短语，我们只监听 `selectionchange`——选区位于阅读区（用 `getSelectionInfo()` + `inReadArea()` 判定）且非空且**跨越 >1 个词**时，把 `.rd-bubble` 气泡（查词/翻译/标记）挂到选区上方（复用 L212 `showBubble`，其定位逻辑已支持选区 rect）。
- 选区只有 1 个词时（长按系统默认只选一个词）同样弹气泡，用户可直接确认或拖动手柄扩选（气泡随 selectionchange 重新定位）。
- **压制 Android 系统菜单**：阅读区内 `contextmenu` 事件 `preventDefault()`（touch 长按在 Android 触发 contextmenu）；现有 L1051 右键直查逻辑对 touch 来源 `preventDefault` 后**直接返回不查询**（长按场景由 selectionchange 气泡接管，避免重复查询）。
- **iOS 不较劲**：iOS Safari 的系统文本菜单（拷贝/查询）压不掉，接受它与我们的气泡并存，用户点我们的。`-webkit-touch-callout: none` 仅对 iOS 上的非文本元素（图标/装饰）加，正文不加（不干扰原生选区）。
- `user-select` **不禁止**——长按选短语依赖原生选区。
- 气泡内的「标记」按钮逻辑复用现有 `isNoteableSelection` 判定。

**1.3 查词/翻译结果改底部面板（bottom sheet）**（reading.css + reading.js 少量分支）

- 不新增第二套 DOM：给 `rd-card`（查词结果表单，含词性/释义/例句/来源/保存，reading.js L351 起）加形态切换——720px 断点下 `.rd-card` 由「选区旁浮动小卡」变为 **fixed 底部 sheet**：`position: fixed; left: 0; right: 0; bottom: 0; width: 100%; max-height: 70dvh; overflow-y: auto; border-radius: 顶部圆角、底部直角`。
- 原 `.rd-card-grip` 拖动手柄在 720px 下隐藏（CSS `display: none`，不动 JS）。
- `.rd-bubble`（确认气泡）720px 下**加大点击热区**：按钮 `min-height: 40px; min-width: 48px`，防误触。
- **虚拟键盘处理**（必做）：sheet 内有输入框（词性/释义/例句/来源），键盘弹出会盖住 fixed 底部面板。用 `visualViewport` 监听：键盘弹出时给 sheet 设置 `transform: translateY(视口高度 - visualViewport.height - visualViewport.offsetTop)` 或等效上移，键盘收起时复位；同时对 sheet 内获得焦点的输入框 `scrollIntoView({block:'nearest'})` 兜底。
- 例句来源、词库双向联动、入库管道**零改动**——表单字段与提交流程完全复用。
- **触屏分支不读 `mouseMode`**：正文点词=确认查词、控件点击=作答，区域天然分流，「作答/查词」模式开关（L2125）在触屏事件分支中不参与判定；开关照常显示供桌面窄窗口使用。

### 第 2 步：答题手机化（隐藏悬浮球，底部题目条 + 半屏面板）

**2.1 悬浮球变底部题目条**（reading.css + reading.js）

- 复用现有 `#rdQBall` DOM（index.html L439-442），720px 断点下 CSS 变形：由「右下角 58px 可拖圆球」改为**底部固定通栏题目条**（`position: fixed; left: 0; right: 0; bottom: 0; height: 48px; border-radius: 0; width: auto`，内部布局横排：题号 + 「展开答题」提示 + 未答题数徽标）。
- 触屏/窄屏分支禁用 qball 的 `pointerdown` 拖动逻辑（L1781 起）与位置记忆（`rd-qball-pos` localStorage 不读写）；720px 下 `touch-action` 恢复默认（CSS 覆盖，不动 JS 判定）。
- 点题目条 → 展开题目面板（见 2.2）。题目条常驻（作者已确认通栏 48px 形态），正文区底部加对应 padding 防遮挡。

**2.2 题目卡变半屏上滑面板**（reading.css + reading.js）

- 复用现有 `#rdQCard` DOM（L443-452，含 tabs、body），720px 断点下变形：`position: fixed; left: 0; right: 0; bottom: 48px; width: 100%; max-height: 60dvh;` 底部滑入动画（`translateY` 过渡，与侧栏抽屉 `.sidebar` L2654 同款节奏）。
- 第一版**固定 60dvh 不做拖拽变高**；面板顶部画装饰性把手条（纯视觉，无交互），待用户反馈再决定是否做拖拽变高。
- 720px 下禁用：qcard 头部拖动（L1816）、resize 手柄与尺寸记忆（L2084、`rd-qcard-size`），`resize: none`。
- 展开态下文章上半部分仍可见可滚动；答完点「✕」收起回正文，单手闭环。

**2.3 判分/解析在手机上的呈现**

- 「问AI」浮窗（`.rd-ask`）**本次不动**（单独议）。
- 单题卡内的选项列表（`.rd-opts`）已有 560px 单列降级（reading.css L928），保持。

**2.4 断点决策**

- 题目条/半屏面板/底部 sheet 的 CSS 形态统一用 **720px media query**（与主界面手机断点一致，style.css L2589）。
- 查词/长按的 JS 行为分支用 **pointerType 判定**（非断点）——触屏笔记本窄窗口下鼠标查词不受影响，宽平板触屏查词也能用。
- 两者独立：CSS 跟断点走，JS 行为分支跟 pointerType 走。

### 第 3 步：顶栏收纳（720px 收进「更多」菜单）

**3.1 保留与收纳**（index.html + static/script.js + style.css）

- 720px 断点下顶栏 `#headerActions`（index.html L41-63）只显示：**题库**（抽屉入口，必须常驻）、**账号名**、**退出**、新增**「更多」按钮**（`⋯`）。
- 新增「更多」按钮（720px 下显示、桌面隐藏），点击弹出竖排下拉菜单。
- **菜单项动态镜像**：菜单**打开时**由 JS 克隆 `#headerActions` 内当前**可见**（非 `hidden`、非 720px 常驻项）的按钮到菜单容器——各按钮的视图切换逻辑（`rd-toolbar-only`、`mode-sa-only`、`mode-kill-only`、`hidden` 属性管理）零改动，克隆时机保证状态同步；菜单项点击 `click()` 转发到原按钮后关闭菜单。
- 点菜单外任意处关闭菜单。不做 Esc 关闭（全站无此先例）。

**3.2 顶栏其他**

- 品牌 + 统计保留现样式；统计过长时允许换行，不强制单行。

## 五、验收标准（每步独立验收，真机：作者手机，MIUI/Android Chrome 为主，iOS 顺带过一遍）

**第 1 步（查词）**：
1. 手机点正文新词 → 词上方弹「查词/翻译」气泡；点「查词」→ 底部释义面板出结果；面板内可修改词性/释义/例句并正常入库，入库后正文出现持久标记。
2. 点已入库标记词 → 直接出释义（本地，无网络请求），不弹确认气泡、不调 AI。
3. 长按词/短语 → 系统选中 + 气泡挂选区上方（Android 无系统菜单）；拖动选区手柄，气泡跟随；点「查词」整短语进面板。
4. 长按后手指滑动（滚动页面）→ 选区清除、气泡消失，不触发查询。
5. 单击滚动页面（快速滑动中触屏）→ 不弹气泡不查询。
6. **键盘弹出时**：面板内点例句输入框 → 键盘弹出后面板被顶上去，输入框与「保存」按钮均可见可操作；键盘收起后面板回位。
7. 判分前的选项、挖空、词库条点击仍是作答行为，不触发查词。
8. 桌面端回归：双击/右键/模式开关行为与改前完全一致。

**第 2 步（答题）**：
1. 手机进阅读视图全程不见右下角圆球，见底部题目条；点条展开半屏面板，文章上半屏可见。
2. 面板内完成选词填空/匹配/仔细阅读作答与判分，答完收起回正文，全程单手可达。
3. 悬浮球拖动、位置记忆、卡片拖动/resize 在触屏/窄屏上全部失效；桌面端全部如常。
4. 无横向滚动条；题目条不遮挡正文末行（底部留 padding）。

**第 3 步（顶栏）**：
1. 720px 下顶栏只有 品牌/统计/题库/账号/退出/更多 一行，无换行无横向滚动。
2. 「更多」菜单内所有收纳按钮可见可用，点击功能正常且菜单关闭；各视图切换（刷题/阅读/简答/模考）后菜单内容正确同步。
3. 桌面端顶栏布局零变化。

## 七、风险与注意点

1. **`selectionchange` 与点词分支的时序**：单击瞬间可能触发瞬态 selectionchange——气泡逻辑必须校验选区非空且稳定（`getSelectionInfo()` 拿到多词文本才弹），空选区时 dismiss 气泡。
2. **Android contextmenu 双触发**：touch 长按会同时触发 contextmenu（现有右键直查逻辑）与 selectionchange 气泡——contextmenu 分支必须对 touch 来源 preventDefault 后直接返回，查询只从气泡确认走，防止重复调 AI。
3. **runLookup 烧真 Key**：验收时后端 `/api/reading/lookup` 走 DeepSeek 代理；开发自测用 monkeypatch/本地 mock，真机验收由作者控制调用次数。
4. **`hidden` 属性与 CSS 冲突**：题目条/qcard/sheet 复用现有 `hidden` 管理逻辑（进入阅读视图才显示），新形态只做 CSS 覆盖，不改 JS 显隐时序，避免重现「悬浮球永久消失」旧坑（行内样式与 hidden 冲突的 Lessons Learned）。
5. **更多菜单克隆时序**：菜单打开时克隆而非初始化时克隆，否则视图切换后菜单内容过期。
6. **visualViewport 兼容性**：现代浏览器均支持；老浏览器兜底 `scrollIntoView`，不做特性检测分支。
7. **PowerShell/编码**：本环境 PS 5.1 控制台 GBK，涉及中文路径/消息时按项目惯例用工具链而非命令行硬编码。
