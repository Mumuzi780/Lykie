# 顾问：在现有基础上改成「会想再开口」的 Lykie

> 给你看的改法。测试时思考可以露出来；正式对用户隐藏。API 自备，多一次调用不是取舍条件。  
> 日期：2026-09-21  
> 对照现状：闲聊主路径在一次 `build_messages` + 一次 `chat_completion` 里同时做人设、判断和开口；开口之后才另有抽取（口吻、印象、事实）。

---

## 先定一句

正式上线要藏的是**给用户看的思考**，不是把思考这步关掉。  
测试和上线跑同一条链路；差别只是接口和面板把不把思考交出来。

---

## 现有链路里什么留下

这些已经是「人」的骨架，不要为了像 agent 拆掉：

- 错字跟进直接沉默（改上一句、不再回）
- 感情层只注入当前许可（`relationship_brief`）
- 印象、事实、口吻在**说完之后**再抽取写入——这是记忆，不是她说话前的思考
- `[不回复]`、直攻才降层
- 开场手写剧本不走模型
- 档案没有的私事不现编

要动的是中间：**开口那一次生成太胖。** 在它前面加一次「只决定、不说话」的调用，开口那次变瘦。

你现在开口之后已经会再调模型做抽取。前面再加一次决定，是同一种用法，不是新品种。

---

## 改成什么样

每一轮闲聊（以及「问问」）变成三截，仍在现有接口里面：

```
用户这句话
    → ① 思考（模型，低温）：这一轮干什么、要不要查
    → ② 查（程序，不是模型）：只按思考点名的东西去取
    → ③ 开口（模型，保持现在的口语温度）：只根据决定和查到的几条说话
```

① 的输出给测试面板。③ 的输出才进聊天气泡，才写入 `chat_tail`。  
**思考原文不要写进聊天记录**，否则下一轮她会学着把内心戏说出来。

### ① 思考：只出结构，不出她的台词

输入要短，不要把整份 `prompt_core` + 整份档案再贴一遍。给它：

- 最近几句对话
- 当前这句话
- 当前感情层的那一小段许可（现成的 `STAGE_BRIEFS`）
- 印象里有没有未道歉的冒犯（有/无即可）
- 现在是不是「问问」模式、有没有当前题

请它只返回固定字段，例如：

| 字段 | 含义 |
|------|------|
| `action` | `thin` 薄回 / `schedule` 按日程 / `teach` 讲题 / `deflect` 少说或停分享 / `push` 顶或扣住 / `silence` 先不回 |
| `need` | `none` / `timetable` / `question` / `profile`（可多选，但宜少） |
| `profile_topics` | 若 need 含档案：只点名要看的块，如课表、怕水、志向，不要「全部」 |
| `why` | 一两句，给人看的理由 |

温度低一些（例如 0.2）。想不好就 `action=thin`、`need=none`，不要在思考步里编她的一天。

`silence` 对应你已经有的 `[不回复]`：开口步可以跳过，直接走现有的沉默与降层逻辑。

### ② 查：程序按名字取，不要让模型自己翻全文

思考点了什么，代码就取什么，塞进开口那一轮：

| need | 现在手里已有的材料 |
|------|-------------------|
| `timetable` | 档案里的课表 + 当前时间（你已有 `format_now_block`） |
| `question` | 现成的 `format_question_block`（问问模式，或她认定这轮在讲题且面板上有当前题） |
| `profile` | 只摘 `profile_topics` 点到的几段，不注入整份 `self.txt` |
| `none` | 开口步不带档案正文 |

这一步是 if/分支，不必上模型的 function calling。对「她是人、工具在身后」更稳：模型不会在气泡里念出调用过程。

查不到（档案未写、没有当前题）：开口步收到「没有这条」，按现有规矩含糊或不答，不现编。测试面板上让 `why` 旁边能看到「查了什么、是空的」。

### ③ 开口：人设还在，但不再兼任法官

系统提示留下短核：她是谁、不认程序、不嘴硬、按本层冷热、短句、`[不回复]` 的格式。  
再加上思考给出的 `action`，以及②查到的几条。  
最近对话仍要有，否则接不上话。

口吻纠正、监督案例：不要每轮全文。第一版可以先少带（例如只带与这句最像的一条，或先不带），避免她又变回在背判例。印象里「未道歉」若思考已经选了 `push`，开口步只要一句「这轮要顶，不要先交答案」即可。

档案标注块 `%%档案`：从开口步拿掉。缺不缺档案改由思考的 `need` / 查空来决定，测试面板用思考结果代替现在的「请补全」。正式用户看不见这块。

---

## 测试露出来、正式藏起来

和现在的 `profile_notes` 一样：服务端算完，响应里多一个字段，例如 `think`。

- 测试：面板在气泡旁显示 `action`、`need`、`why`、查到了什么。你要看的就是她为什么这样回。
- 正式：请求不带调试开关时，响应里不放 `think`；面板不渲染。思考步照跑。

开关放服务端（环境变量或仅作者账号），不要只靠前端隐藏——否则接口里仍是明文。

聊天记录、分享、对方屏幕：永远只有③。

---

## 建议的改动顺序

一次改完容易不知道是思考错了还是嘴错了。按这个顺序，每步都能用你现在的聊天测。

1. **只加思考，开口暂时仍用现在的胖提示。**  
   思考结果进测试面板，不参与开口。你先看 `action` / `why` 像不像她该有的判断。不像，只改思考用的短提示。

2. **开口改为读 `action`，档案改为按 `need` 摘取。**  
   胖提示里的整份档案、整份监督先拿掉。人设短核还在。这时才比较「聪不聪明」。

3. **`%%档案` 退出开口。**  
   补全提示改绑思考：该查的档案是空的，测试里提示你去补 `self.txt`，不要让她编。

4. **再考虑主动开口、多工具。**  
   课表和当前题这两件就够支撑「会查再讲」。词汇库、文件夹之类以后她真要用再加，不要第一版就做很多工具。

「问问 Lykie」可以和第 2 步一起：思考若是 `teach`，一定 `need=question`，开口只用题目和解析，不会就支吾。这是最容易感到「聪明了」的一条。

---

## 和「像 agent」的边界

思考步不要让她规划用户的学习、不要连续调用很多次。一轮里：一次思考、最多一两样资料、一次开口。  
多出来的模型调用仍是你现有的那些：记事实、记印象、记口吻，放在开口之后，不塞进思考。

她对用户仍是短句里的人。测试里你看到的结构字段，就是 agent；用户看到的那几行字，仍是 Lykie。

---

## 一句话

在现在这次开口之前插入「决定 + 按需查资料」，开口变瘦；思考进测试面板，正式响应不带。人设、沉默、降层、记事实都留在原处。先让思考只展示、不驱动开口，对了再让开口听它的。
