# 顾问：Lykie 要不要做成「聪明的 Agent」

> 给你看的架构判断。不是给主仓的改造清单。  
> 日期：2026-09-21

---

## 你卡住的地方

你要的是：**像 agent 一样会自己想、会用手里的信息、显得聪明的 Lykie。**  
现在跑起来的是：**一次大模型调用，前面挂一份很长的人设与禁令，然后直接开口。**

这两件事都合理，但它们不是同一种架构。把第二种不断加长，去逼出第一种的感觉，就会遇到瓶颈——规则越多，她越像在执行说明书，越不像在想。

构想里已经写过一句对的话：技术上可以有感知、记忆、主动、工具；产品上她仍是 Lykie，Agent 是实现方式。现在实现停在「感知靠把材料全塞进提示词，行动只有开口或 `[不回复]`」。

---

## 现在实际是什么

每一轮闲聊大致是：

1. 拼一段系统提示：核（`prompt_core`）+ 时间 + **整份档案** + 当前感情层 + 对这个人的印象 + 关于用户的事实 + 口吻纠正 + 人工监督案例。
2. 带上最近聊天记录。
3. **一次** `chat_completion`，直接生成她说的话（外加档案标注块）。

没有：先决定这一轮干什么、再去查课表或题、再换成她的嘴说出来。讲题是另一条模式（用户点了「问问」才把当前题塞进去），不是她自己决定要不要用工具。

这套对「别演崩、别现编、别认成客服」是有效的。它不负责「像 agent 一样聪明」。

---

## 为什么会觉得不够聪明

聪明感通常来自三步，而不是来自模型更会聊天：

1. **看清这一轮要干什么**（答、少答、讲题、去查、先不说）。
2. **只取用相关的信息**（课表里的今天、这道题的解析、你上次说过的一件事）。
3. **用自己的声音说出来**，思考过程不露面。

现在这三步挤在同一次生成里，还要同时遵守很长的禁止清单和「档案没有就不许说」。模型的注意力花在合规上，留给「想一下再答」的空间就变小。再往 `prompt_core` 里加判断规则，短期能修一句错话，长期会更钝。

另外两处会放大「笨」：

- **档案整份注入。** Agent 的记忆是按需要调取；全塞进去时，她容易忽略真正相关的那一句，或反过来背无关设定。
- **严格不现编。** 这是人设正确（假日常已废弃），但若没有「查得到的东西」可依，她只能含糊、回避、标注补全。用户感受到的是卡住，不是守人设。

所以瓶颈多半不是「模型不够聪明」，而是 **聪明没有一个单独的位置**。

---

## 怎样理解「像 Agent」，才和 Lykie 不打架

不要做成可见的工具 Agent（一步步「我先调用函数」）。那会把她变成助手，和「不自称 AI、是一个人」直接冲突。

适合她的是 **有边界的能动性**：

| Agent 里常见的一块 | 对她意味着什么 | 用户看不看得见 |
|--------------------|----------------|----------------|
| 感知 | 时间、感情层、这一轮口气、当前是不是在题上 | 看不见 |
| 决定 | 这一轮：寒暄敷衍 / 按日程答 / 讲题 / 顶回去 / 沉默 | 只看见结果 |
| 记忆调取 | 只拿出和这句有关的档案与关于你的事实 | 看不见 |
| 工具 | 课表、当前题与解析、你导入的题——她「会」是因为查到了，不是因为编 | 看不见调用，只听见她讲 |
| 开口 | 短句、按层的冷热、不嘴硬 | 这是唯一该看见的 |

她的理想工作是「AI 背后接线的人」。产品上的聪明，正好可以是：**人在前面说话，后面有查题、对课表、记你说过的话。** 这和世界观是同一件事，不必做成第二个聊天机器人。

构想里的核 / 骨 / 皮仍然适用：

- **核**短、硬、几乎不变（她是谁、不认程序、不嘴硬、层的许可）。
- **聪明**放在决定 + 调取 + 必要时查资料，不放在把核写得更长。
- **成长**放在骨和皮（印象、事实、慢变的说话习惯），不靠把整段聊天当唯一记忆碰运气。

---

## 架构是否合理

**作为「守住人的聊天」：合理，而且已经做对了几件难事。**  
时间对齐、感情层只注入当前许可、印象跨清空对话还在、沉默可以不回、档案禁止现编——这些都是角色架构，不是浪费。

**作为「聪明的 agent」：还不完整，缺的是中间那一层，不是再换一个更大的提示词。**

不建议的方向：

- 把她做成通用 ReAct / 编程 agent，对用户暴露步骤。
- 为了显聪明而放开现编（人会漂，核会丢）。
- 继续把每一条坏回复都写成新的全局禁令（提示词会变成判例汇编，她更不会临场判断）。

建议的方向（思路，不是施工单）：

1. **开口之前有一次不展示的判断。** 只输出这一轮的动作：答事实、讲题、少说、顶、沉默。判断可以很窄，不必再写一篇性格论文。
2. **档案和监督案例改成调取。** 课表、喜好、怕水不要每轮全文进上下文；监督案例只在「这一轮问法相近」时带一条。核保持短。
3. **需要事实时才查。** 问「现在有没有课」→ 用日期对课表再让她说；点了题或她认定在讲题 → 用题库解析，不会就支吾。查不到就含糊，仍不编。
4. **第二次生成才是她的嘴。** 只给：核的摘要、这一轮动作、查到的几条事实、最近几句对话。合规和聪明分开，聪明才有地方站。

这样她会显得聪明，是因为 **答得准、接得上、知道什么时候不说**，不是因为话更长或更像客服。

---

## 和产品边界

学习站仍然免费、算力不由站点长期垫付——若「先判断再开口」要两次调用，那是成本，要用在闲聊主路径上时你再决定是否值得。讲题可以优先：用户点「问问」时本来就该查题再讲，一次查资料 + 一次用她的嘴，聪明感最明显，也最贴「接线的人」。

主动找你说话（高关系才明显）是另一条能动性，和「每一轮更会想」可以分开做，不必绑成一个大 agent。

---

## 一句话

架构里 **人设这条路是合理的**；瓶颈是你想要的聪明被放进了同一次、被禁令占满的生成里。  
把 Agent 理解成她身后的接线（先决定、再查该查的、再说话），而不是把 Lykie 换成一个看得见的 agent——这条和人设、和「想当 AI 背后的人」是对齐的。
