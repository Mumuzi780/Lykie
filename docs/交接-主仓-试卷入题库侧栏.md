# 交接规格：试卷入题库侧栏（影子卷节条目 + 文件夹归档）

> 作者拍板（2026-10-16）：整卷一条记录、四节为入口影子条目、复用题库文件夹体系、答题逻辑不变。
> 本规格为定稿，执行按此文件；与旧文档冲突以本文件为准。

## 定性

- **一张卷 = readings.json 里的一条 text 记录**（原子单位）。侧栏的「选词填空/段落匹配/仔细阅读一/仔细阅读二」是它的四个**入口投影**，不是独立数据。
- 答题状态（answer_key/answers/judged/revealed）、查词标记、AI 出答案全部挂在卷记录上，现有一切逻辑不动。
- bank.json **零写入**：斩题/模考/错题本/分享天然看不见卷条目，零回归风险。
- 文件夹用**题库现有文件夹实体**（真实可改名/排序，存于 bank 存储的 folders 集合），不另造体系。

## 数据层（lykie/readings.py + lykie/bank.py 或存储层）

1. `text` 记录新增字段：
   - `folder_id: str`（挂在哪个文件夹；普通文章为 None → 未分类）
   - `archived: bool`（默认 False；旧记录无此字段按 False 读）
   - `is_paper: bool`（导入时检测 Section A/B/C 结构自动置 True；普通文章 False）
2. 新函数（readings.py，全部走既有原子写）：
   - `list_papers(username)` → `[{id, title, folder_id, archived, is_paper, sections}]`（sections 含各节 key/kind/label/questions 数，供侧栏渲染）
   - `set_paper_folder(username, text_id, folder_id)`（None=未分类；校验文件夹存在）
   - `archive_paper(username, text_id)` / `restore_paper(username, text_id)`（恢复回原 folder_id，语义对齐题库归档）
3. 普通文章（is_paper=False）继续走现有列表页管理，**也并入侧栏**（未分类下，单条目，点击进阅读视图）——旧文章不丢入口。

## API（app.py）

1. `GET /api/banks`（改造，不新增）：响应体新增 `papers` 键（list_papers 输出）。banks 键原样保留。
2. `POST /api/reading/paper/move`：`{text_id, folder_id}` → set_paper_folder；权限校验同其他 reading 路由（当前用户自己的 readings.json）。
3. `POST /api/reading/paper/archive`：`{text_id}` → archive_paper。
4. `POST /api/reading/paper/restore`：`{text_id}` → restore_paper。
5. 导入侧不动：`POST /api/reading/text` 与 PDF 上传路由在**保存成功后**调卷检测（build_sections 结果含 bank/match/choice 任一 kind 且总题数 ≥ 10）→ is_paper=True + 自动建文件夹：文件夹名=用户填的标题（如「2026-6第三套」），已存在同名文件夹则复用；`folder_id` 挂上。普通文章跳过。
   - 注意：检测用**已入库的 build_sections 输出**，不重复解析。

## 前端（script.js 侧栏 + reading_view.html/js + reading.html 文案）

### 侧栏（script.js）

1. `/api/banks` 响应处理：读取 `papers` 键。
2. 右栏列表渲染：真实题库之后追加卷节条目（按 folder_id 分组跟随文件夹视图）：
   - 卷节条目形状 `{type:'reading', text_id, sec_key, sec_label, badge:'卷'}`
   - 一张卷在**其文件夹下展开四个节条目**：选词填空（N 空）/ 段落匹配（N 题）/ 仔细阅读一（N 题）/ 仔细阅读二（N 题）；普通文章单条目（无「卷」徽章）
   - 未分类视图：无 folder_id 的普通文章 + 未建文件夹的卷（若导入时建夹失败兜底）
3. 点击卷节条目：`location.href = '/reading/<text_id>?sec=<A|B|C1|C2>'`（普通文章无 sec 参数）。
4. 拖拽（复用现有 drag 全局状态 + 双栏互斥判定）：
   - 卷节条目可拖：落到左栏文件夹 = **整卷** set_paper_folder；落到归档抽屉 = **整卷** archive_paper；拖出至根区 = folder_id=None
   - 归档抽屉视图：显示整卷单条目（title + 「卷」徽章 + N 题），恢复拖出 = restore_paper 回原文件夹
   - 抽屉里不展开四节（卷是原子单位）
   - 真实题库拖拽路径零改动
5. 「卷」徽章样式（style.css 或 sa.css 少量新增）：小圆标主题色，区别于题库条目。

### 阅读视图（reading_view.html + reading.js）

6. URL `?sec=` 参数处理：页面加载后滚动到对应 `.rd-pass[data-key]` + 打开悬浮球卡**预选对应 tab**（A→bank tab、B→match、C1/C2→choice）。
7. 球内 tab 标签改名：`选词填空 / 段落匹配 / 仔细阅读一 / 仔细阅读二`（shortLabel 函数）。
8. 导入成功跳转不变（进阅读视图）；试卷导入成功后提示文案「试卷已入库：文件夹《标题》」。

### 试卷页（reading.html）

9. 文案：「文章」→「试卷」（列表标题/新建按钮/空状态）；条目保留普通文章与试卷混排（现状数据如此）；**不提供**删除/改名/移动入口（管理动作集中于侧栏拖拽 + 导入时建夹，试卷页退化为导入 + 浏览入口）。
   - 现有删除/改名按钮若存在于列表项：保留（已有数据需要管理出口），但移入「管理」折叠区或保持现状——**执行时以最小改动为准，不重构列表页**。

### 资源版本

10. script.js bump（style.css?v= 与 script 版本号按现有 bump 惯例）；reading.js/reading.css v=15 → 16；reading.html/reading_view.html 为模板无需版本。

## 明确不做

- 斩题/模考/错题本/分享对卷条目的任何感知
- 卷节条目的独立删除/改名/排序（卷是原子单位；标题改 = 卷标题改，本期入口不做）
- 听力/作文/翻译节的导入（PDF 仍只取阅读部分；将来补全=重新导整卷 PDF 覆盖）
- 普通文章的文件夹挂载（普通文章固定未分类；要挂文件夹的时机等真出现再说）
- /reading 顶栏入口移除（保留）

## 验收标准

1. **8 份真题 PDF 逐份回归**：导入后自动建夹（名字=标题）、四节条目出现在文件夹下、badge 正确、点击直达对应 Section 且球卡预选 tab
2. **归档流**：拖卷节条目入抽屉 → 抽屉显示整卷单条目；拖出 → 回原文件夹四节展开；期间斩题抽题一切照旧
3. **普通文章**：老子篇出现在未分类、点击进阅读视图、无「卷」徽章；其查词/标记/作答零回归
4. **数据隔离**：bank.json 在整个流程序列前后 diff 为零（仅 folders 可能新增）
5. **多账号**：papers 只来自当前用户的 readings.json，互不可见
6. **旧数据**：无 folder_id/archived/is_paper 字段的旧 text 记录按未分类/未归档/普通文章读，功能正常
7. **URL 定位**：`?sec=C2` 直接打开时滚动到 Passage Two 且球卡预选仔细阅读二 tab
8. 侧栏拖拽不引入题库拖拽回归（题库条目移动/归档/恢复跑一遍既有路径）

## 执行顺序建议

数据层（readings.py 四函数 + 字段）→ API（1 改造 3 新增 + 导入钩子）→ 侧栏渲染/点击/拖拽 → sec 定位与 tab 改名 → 文案 → 全量回归。

### 已知边界

- 侧栏卷节条目不支持右栏内排序（无 sort_order 概念，固定排在题库之后、模考合集之前）
- `?sec=` 定位与球卡预选为纯前端逻辑，node 沙箱无法覆盖 DOM 部分，待用户浏览器实测
- 普通文章（is_paper=False）固定未分类、不可拖拽归档——归档仅试卷可用（规格明确不做普通文章挂夹）
