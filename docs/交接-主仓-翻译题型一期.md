> 推演依据见 `docs/新功能推演方法.md` 首个案例。本规格为第一批：零特色搬运 + 逐句推进 + 阶梯提示。

## 目标

四级整卷 PDF 中的 Part IV Translation（汉译英段落）：

1. 随整卷导入管道自动识别为独立节，原封不动呈现中文原文
2. 逐句作答：中文按句切分，一次只呈现一句，做完再出下一句
3. 阶梯提示：每句可按需获取词块提示，三阶逐级揭示（首字母+词长 → 中文语境 → 完整词块），不给直接答案
4. 对答案：AI 按句生成参考译文为默认；用户可手动粘贴书本答案覆盖；两版可并存展示

## 改动文件与内容

### 1. `lykie/readings.py` — 解析管道

**新增翻译节识别**：`build_sections()` 中，在现有 A/B/C 节之外识别 `Part IV Translation` 节（正则容错 `Part\s+IV\s+Translation`，大小写不敏感；Directions 段剔除，规则同 `_drop_structure_lines` 纪律）。

产出新节形状：

```python
{
  "key": "T",
  "kind": "translation",
  "label": "Part IV · 翻译",
  "source_cn": "整段中文原文",
  "sents": ["近年来，……", "截至2025年3月底，……", ...],  # 按句切分
}
```

- `sents` 切分规则：按 `。！？；` 切，句末标点保留；切分在后端完成（前端不重复实现，与软换行解析纪律一致：同一规则只在一处定义）
- 无 Part IV 标记的卷不产出翻译节，现有卷解析零影响

**`_paper_sections()` 特判**：翻译节无 `questions`，现有逻辑会跳过——需特判纳入投影，形状 `{"key": "T", "kind": "translation", "label": "翻译", "count": 1}`。`detect_paper()` 不改（它只看 bank/match/choice 题数，翻译节不影响卷判定）。

**作答与提示存储**：text 记录新增 `translation` 字段（懒创建，旧记录无此字段视为未作答）：

```python
"translation": {
  "answers": {"0": "In recent years, ...", ...},   # 句 idx → 用户译文
  "revealed": false,                                 # 是否已对过答案
  "manual_ref": "",                                  # 手动粘贴的整段参考译文
  "ai_ref": {"sents": ["...", ...], "full": "..." }, # AI 按句参考（LLM 生成时缓存）
  "hints": {"0": [ {"cn": "政策", "s1": "p_____ (6)", "s2": "政府出台的…", "ans": "policy"}, ... ]},
}
```

新增函数：`get_translation(username, text_id)`、`set_translation_answer(...)`、`set_translation_reference(...)`（原子写入，纪律同 `save_prose`）。

### 2. `app.py` — 路由

```
POST /api/reading/<text_id>/translation/answer   {"sent_idx": 0, "text": "..."}   存单句译文
POST /api/reading/<text_id>/translation/hint     {"sent_idx": 0}                  生成/返回该句阶梯提示
POST /api/reading/<text_id>/translation/reveal   {}                               对答案：确保参考译文就绪并置 revealed
POST /api/reading/<text_id>/translation/reference {"text": "..."}                 手动粘贴/更新参考译文
GET  /api/reading/<text_id>/translation                                           返回 translation 全量状态
```

**阶梯提示生成**（hint 路由）：带该句中文（不带用户译文、不带参考译文）调 `lykie_llm.chat_completion`（json_mode，温度 0.3，`disable_thinking=True`），prompt 要求输出 3~6 个该句核心词块/表达，每个含 `cn`（中文）、`s1`（首字母+词长掩码，如 `p_____ (6)`）、`s2`（中文语境提示）、`ans`（完整英文词块，含搭配如 `introduce a policy`）。`_parse_llm_json` 带正则降级。结果缓存进 `translation.hints[sent_idx]`，再次请求零模型调用。已缓存的提示请求不烧 Key。

**参考译文生成**（reveal 路由）：优先级 `manual_ref` > `ai_ref`。两者皆无时调 LLM（json_mode，温度 0.3），prompt 给中文全段 + 句数，要求输出按句对应数组 + 整段，标记为 AI 生成。生成失败：返回 `ok: false`，前端提示可手动粘贴，不阻塞（降级纪律同查词卡片）。生成成功缓存进 `ai_ref`，重做试卷不重复调用。

**LLM 失败纪律**：hint 与 reveal 的模型调用失败均不落半截数据，前端可原样重试（纪律同问 AI）。

### 3. 前端 `static/reading.js` + `templates/reading_view.html` + `static/reading.css`

**节接入**：
- `sections` 过滤条件（现 `(s.questions||[]).length || (s.bank||[]).length`）追加 `|| s.kind === 'translation'`
- tab 渲染新增 `renderTranslationTab(s)`，tab 名「翻译」
- 静态资源 bump 版本号

**作答界面**（逐句推进）：
- 顶部显示当前句 `第 i/N 句` + 中文原句（句末标点保留）
- 下方 textarea 输入该句译文；「下一句」按钮：句 i 译文非空才可进（已写内容存 `answers[i]`，返回上一句可改）
- 最后一句完成后出现「对答案」按钮；对答案前参考译文不可见（前端不请求 reveal 即拿不到）
- 对答案后：整段视图——每句并排展示「你的译文 / AI 该句参考」，底部整段参考译文（manual_ref 存在时优先展示并标注「书本参考」，ai_ref 标注「AI 参考」；两者都有时并存两块）
- 重做不清空作答与参考（同问 AI 纪律）

**阶梯提示交互**：
- 每句作答区一个「提示」按钮：首次点击请求 hint（loading 态），返回后仅显示所有词块的 `s1` 行
- 词块行可再点：第二击显示 `s2`，第三击显示 `ans`（逐阶揭示，每阶用户先自己试）
- 提示行以折叠列表呈现，不打断输入焦点

## 分步实施顺序

1. 解析管道：翻译节识别 + sents 切分 + `_paper_sections` 特判（存量卷刷新即可见翻译节）
2. 存储与路由：translation 字段 + 5 条路由（hint/reveal 的 LLM 调用先留桩返回固定 JSON，第 4 步接真）
3. 前端：节接入 + 逐句作答 + 对答案展示 + 手动粘贴入口
4. LLM 接入：hint 与 reveal prompt + 缓存 + 降级
5. 联调验收

## 验收标准

- 导入含 Part IV 的整卷 PDF：翻译节正确分出，中文段落完整不粘连，Directions 剔除；不含翻译的卷解析结果与现状完全一致（回归）
- 逐句作答：前进/回退改写、未写完不能跳句、对答案前看不到任何参考
- 阶梯提示：同一句重复请求零额外模型调用（缓存验证）；断网时提示按钮报错可重试，作答不受影响
- 对答案：无 manual 时 AI 按句参考 + 整段；粘贴 manual 后书本优先；再次进入对答案视图零模型调用
- 旧记录（无 translation 字段）打开不报错，视为未作答
- LLM 调用均走 json_mode + `_parse_llm_json` 降级，垃圾输出不崩

## 明确不做（本批次）

- 不做 AI 打分、逐句批改（谁翻得好/偏在哪）
- 不做卡点沉淀录词（参考译文划词进资产库）
- 不做主干模板提示
- 不做翻译题进斩题/模考/错题管道（保持影子卷投影定位）
