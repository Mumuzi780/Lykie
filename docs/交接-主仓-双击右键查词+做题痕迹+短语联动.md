# 交接规格：鼠标模式 · 双击右键查词 · 做题痕迹 · 短语联动

> 2026-11-11 定稿（v2，模式版）。依据：2026-10-18「新功能路线」拍板（右键+双击并存
> 查词手势、短语确认制）+ 2026-11-11 两轮讨论结论。v1 的「排除区」方案已废弃，
> 按作者拍板改为**鼠标模式层**：查词模式下作答控件全部静默，选项/词库词可查；
> 作答模式自带笔迹直标。
>
> 实现顺序：模式层 → 双击 → 右键 → 短语联动 → 笔迹（前四块共用一条管道；
> 笔迹是新增数据面，独立验收）。

## 零、总原则

- 四项功能全部**复用既有查词管道**（`runLookup` → `/api/reading/lookup` → 查词卡片
  → `/api/assets/vocab`），不新建第二条查询链路。
- 短语联动**单次调用返回双结果**，确认后零额外模型调用（2026-10-18 拍板原文）。
- 做题痕迹是**笔记，不是作答态**：「重做」不清除痕迹；痕迹与查词标记（.rd-mark
  虚/实线）是两套独立标记，样式与数据都分开。
- **挖空控件永不参与笔迹**：无论笔迹怎么划，挖空保持原样不高亮、不影响作答逻辑。

## 一、鼠标模式层（新顶层状态）

### 交互矩阵

| 手势 | 作答模式（默认） | 查词模式 |
|---|---|---|
| 单击选项/挖空/选题控件 | 正常作答 | **全部静默**，控件当纯文本 |
| 拖动划选 | 划选 → 气泡（查词/翻译/标记），点「标记」才落笔迹 | 划选 → 气泡（同左，两模式统一） |
| 双击 | 仅正文/题干直查（选项/词库不启用） | **全区域**直查，含选项、词库 |
| 右键 | 全区域可查（右键不触发 click，天然无冲突） | 全区域可查 |

> 2026-11-11 修订（作者体验后拍板）：作答模式原为「拖动 ≥4px 直标笔迹」，因与
> 辅助阅读划选冲突改为气泡确认制——划选只弹气泡，点「标记」按钮才落痕，
> 不点不落。两模式气泡与标记入口完全统一。

### 实现要点
- 顶栏工具条（rd-toolbar-only 区）加分段开关「作答 | 查词」，`localStorage`
  持久化（key 建议 `rd-mouse-mode`），init 时读取，默认 `answer`。
- 模式开关是**唯一状态源**（全局变量 `mouseMode`），所有交互分支读它判定，
  禁止在各 handler 里散落 `classList.contains` 式的模式推断。
- 查词模式静默作答的实现：在作答 click 入口（选项选择、挖空点开 picker、
  段落匹配选题等既有 handler 顶部）加一行 `if (mouseMode !== 'answer') return;`。
- 模式切换时收起气泡/卡片/picker，清当前拖拽态，避免跨模式残留交互。
- 切换开关本身不依赖键盘，点击即切；样式与既有分段按钮一致（参考导入页分区）。

## 二、双击查词

- 监听 `document` 的 `dblclick`（与现有 `mouseup` 气泡弹出同层）。
- 触发条件全部满足才直查：
  1. `getSelectionInfo()` 有效且选区在阅读区内（正文 `.reading-p`、题干
     `.rd-q-p` / `.rd-match-stem`；**查词模式下额外放开 `.rd-bank-item`、
     `.rd-opt`**——此时控件已静默，双击即查词）；
  2. 选中文本匹配单词形态 `/^[A-Za-z][A-Za-z''-]*$/`（字母词，允许撇号/连字符；
     数字、标点、混合文本**不自动查**，只弹既有气泡）；
  3. 事件目标不在浮层/球上：`closest('.rd-picker-panel, .rd-qcard, .rd-card,
     .rd-bubble, .rd-qball, button, .rd-note')` 为 null。
     （作答模式下 `.rd-blank, .rd-opt` 命中时跳过直查——控件点击语义优先。）
- 满足 → `showBubble(info)` 后立即 `runLookup('lookup', info)`：气泡充当
  「查询中…」loading 指示，卡片返回后 `openCard` 自动收掉气泡，视觉连续。
- 已知无害现象（不修）：第二次 `mouseup` 的 `setTimeout(0)` 气泡任务先于
  `dblclick` 执行，气泡闪现一帧后 dblclick 接管。
- 同词重复双击命中后端缓存，零模型调用（既有 `find_cached_lookup` 免费继承）。

## 三、右键查词

- 监听 `document` 的 `contextmenu`，**两模式行为一致**（右键不触发 click，
  与作答无冲突），判定顺序：
  1. 事件目标在浮层/球/卡片内（closest 黑名单）→ **放行原生菜单**；
  2. 存在非空选区且鼠标点位于选区内 → 直接查**整个选区**（天然支持右键查短语）；
  3. 否则取光标处单词：`document.caretRangeFromPoint`（Chrome/Safari）fallback
     `document.caretPositionFromPoint`（Firefox），向两侧扩到词边界
     （字符集 `[A-Za-z''-]`）：
     - 扩出 ≥1 个字母 → 用 Range 选中该词，直接查；
     - 落在标点/空白 → 放行原生菜单。
- 命中并查询时 `preventDefault()`；放行时不拦。
- 查询走 `runLookup('lookup', info)`，气泡做 loading，卡片到了自动收。

## 四、短语联动（确认制）

### 后端
1. `_LOOKUP_PROMPT`（app.py）增加输出要求：

   ```
   若选中词在此句中与相邻词构成常见固定搭配/习语（如 shed 在 shed light on 中），
   额外输出 "phrase" 字段：
     "phrase": {"text": "该搭配在句中的连续原文片段", "meaning": "搭配整体的中文释义"}
   无固定搭配时 phrase 为 null。
   ```

2. `api_reading_lookup`：解析出 `phrase`（须为 dict 且 text/meaning 非空，否则
   置 null），存进 `append_lookup` 的 `result`、透传进响应 `draft.phrase`。
   缓存命中路径同样从 `result` 带出 → **重复查询零额外调用**。
3. `_LOOKUP_PROMPT_NOCTX` 不加 phrase（无语境无从判断搭配）。
4. 新路由 `POST /api/reading/lookup/<lookup_id>/phrase`：
   body `{text, meaning}`。后端：
   - 原 lookup 记录加 `"superseded": true`；
   - 派生一条新 lookup 记录：selection=phrase.text、sentence 同原文、
     result={head: phrase.text, pos: 'phr.', meaning, example_zh 同}；
     **纯本地写入，零模型调用**；返回新记录 id。
   - `get_lookup_marks` 跳过 `superseded` 记录 → 原词不再虚线标，短语接管标记。

### 前端
- 卡片顶部（错误行之下、词头行之上）渲染确认条（`draft.phrase` 存在时）：

  ```
  句中搭配：shed light on —— 揭示、阐明
  [记短语] [只记单词]
  ```

- 「记短语」：调 `/lookup/<id>/phrase` → 成功后：
  - 卡片字段切换：词头=phrase.text、词性=phr.、语境义=phrase.meaning（可手改）；
  - `lookupId` 换成新记录 id（后续「存词」的 imported 落在短语记录上）；
  - `lastSelText` 换成 phrase.text；RD_MARKS 删除原词目、`addMark(phrase.text, …)`，
    `rebuildMarks()`；
  - 确认条消失。
- 「只记单词」：确认条消失，词草稿原样，后续不变。
- 不点确认直接改字段保存 = 隐性「只记单词」。
- translate 模式不涉及。

## 五、做题痕迹（气泡确认制，两模式统一入口）

### 触发方式（一种入口，数据同源）
**两模式均为：划选松手 → 气泡「标记」按钮**（查词/翻译之外的第三按钮）。
选区可锚定时（正文 `.reading-p`、题干 `.rd-q-p` / `.rd-match-stem`，单段落；
选项/词库除外——那是作答控件区）按钮才显示，点击落痕；不点则划选仅辅助阅读，
不产生任何数据。
实现取径：监听 mouseup + `window.getSelection()`，**不做自绘笔迹层**，
高亮在保存成功后由重放器渲染（与查词标记同纪律：记录是唯一事实源）。
（2026-11-11 修订：原「作答模式拖动 ≥4px 直标」因与辅助阅读划选冲突废弃。）

### 锚定模型（关键，跨挖空跳过）
- 段落基准文本 `noteBaseText(para)`：walk 文本节点，**跳过 `.rd-blank` 子树与
  `.rd-opt-key` 子树**，其余 Text 节点字符原样累加。（`.rd-mark` 包裹不改字符，
  无需跳过；挖空回填会变内容，必须跳过。**不要复用 paraCleanText**——它对挖空
  有「回填词替代编号」的语义替换，锚定需要的是排除。）
- **跨挖空拆段**：笔迹区间在 DOM 上连续、但在基准文本中被挖空分隔成多段。
  落痕时把区间按挖空边界切分为 **segments 列表** `[{start, length}, …]`
  （全部在同一段落的基准文本口径上），单条 note 携带全部段。挖空本身不在
  任何 segment 内 → **永不高亮、永不参与**，视觉上笔迹「跳过」挖空继续延伸。
- 存储字段：`{id, text_id, para_index|q_num+q_para_index, segments, text, at}`；
  `text` 为划选原文（各段文本按序拼接）供校验。
- 重放 `wrapNoteSegments(para, segments, text)`：同口径 walk，逐段定位字符区间
  （可跨 text node）切分包裹 `span.rd-note`；段文本 ≠ 存的对应文本 → 该段静默
  跳过（防内容变更错标）；区间已在 `.rd-note` 内 → 幂等跳过。
- 定位字段复用现有四区口径：正文 `{para_index}`；题干 `{q_num, q_para_index}`
  （与 marks 的 posToQNum 一致，note 不用 bank/opt）。
- `rebuildNotes()` 与 `rebuildMarks()` 同级：init、判分重写正文后、切换文章时
  都调用；init 时先全量拆旧再重放（与 rebuildMarks 同纪律）。

### 删除
- 点击已有 `.rd-note` → 弹小浮层「删除标记」→ `DELETE /api/reading/note/<id>`
  → 移除重建。浮层加进「点空白收起」排除清单（reading.js L1622 附近）。
- 「重做」**不**清痕迹（笔记非作答态）。

### 数据与 API
- `readings.json` 顶层新增 `"notes"` 列表（`lykie/readings.py`：
  `append_note / delete_note / get_notes(text_id)`）。
- app.py：`POST /api/reading/note`（校验 text_id 存在、text ≤ 200 字、segments
  非空且 start/length 非负）、`DELETE /api/reading/note/<note_id>`。
- `_reading_view_payload` 增 `"lookup_notes"` → `/api/reading/view` 与 `/` 直链
  渲染自动带上。前端 init 存 `window.RD_NOTES`。

## 六、已知限制（作者已拍板接受，后续再优化）

- **作答模式下整句翻译够不着**：拖动被笔迹占用，划选消失，双击只查单词
  （但双击查词自带整句 example_zh，大部分场景覆盖）。需要划选翻译时切查词模式。
  用得少，后续再优化，本次不做任何特殊逻辑。

## 八、验收标准

**模式层**：①默认作答模式，刷新后记住上次选择；②查词模式下点选项/挖空/选题
全部无反应，切回作答模式恢复正常；③切模式时气泡卡片 picker 收起；
④作答模式选项区拖动是笔迹、纯点击仍是选答案。

**双击**：①作答模式：正文/题干双击直接出卡，选项/词库双击不触发；
②查词模式：选项、词库词双击直接出卡；③双击数字/标点只弹气泡；
④挖空上双击（作答模式）不误触；⑤左键作答无回归；⑥重复双击走缓存。

**右键**：①两模式下正文/选项/词库右键单词都直接查；②有选区时右键选区内查
整个选区；③浮层/球/卡片内右键出原生菜单；④Firefox 走 caretPositionFromPoint
分支（devtools 模拟验证）。

**短语**：①含 "shed light on" 句查 shed 出确认条；②记短语 → 卡片换短语草稿、
原词标记消失、短语标记出现、存词 head=短语且 imported 落短语记录；
③只记单词一切如旧；④二次查询走缓存且确认条仍在；⑤无搭配词不出确认条。

**笔迹**：①作答模式拖动即标，查词模式点「标记」按钮标，两者数据同源；
②划选跨挖空：挖空不高亮、前后两段都亮，作答回填后两段位置不漂移；
③刷新/重进位置一致；④点击高亮可删；⑤重做后痕迹保留；⑥与查词标记视觉互不干扰。

**通用**：`node --check` + `py_compile`；新路由行为测试全过（LLM monkeypatch，
不烧 Key）；静态资源版本号已 bump。

## 九、明确不做

- 痕迹颜色分类、文字备注（MVP 单色高亮）
- 选项/词库区的笔迹（作答控件区，仅查词开放）
- 作答模式下的划选翻译（见「已知限制」）
- 短语多候选、义项自动拆分
- 双击/右键/模式的设置开关（调用设置页整体后置，2026-10-18 拍板）
- 手机端长按查词（另案）
