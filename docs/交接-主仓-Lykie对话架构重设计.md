# 交接：Lykie 对话架构重设计

> 给**主仓**。这是一份架构级规格，不是功能增量。冲突时以本文为准。
> 日期：2026-10-10
> 前置阅读：`lykie/self.txt`（Lykie 人生档案，**不可改**）、`docs/产品定位.md`

---

## 设计原则

1. **她是人，不是 agent。** 一个真人收到消息后的认知是一体的——看到、想起、决定——不存在"先输出 JSON 思考、再查档案、再开口"的三步。模型内部完成全部判断，不暴露结构化中间产物。
2. **单次模型调用。** 一轮对话 = 一次模型调用。上下文一次性注入，模型直接输出回复或 [不回复]。不拆 think→lookup→speak 三段。
3. **真实延迟和不回。** "不回"不是模型输出 [不回复] 再由程序隐藏——而是消息排队或丢弃，用户侧看到的就是"已读不回"或"未读"。回复有打字延迟。
4. **档案是事实，不是提示词。** self.txt 143 行是 Lykie 的真实人生，她"知道"这些，不是"被提示"这些。每轮全量注入——现代模型上下文窗口完全装得下。
5. **情绪靠记忆，不靠计数器。** 真人记得"他刚才骂了我"，不靠 offense_count=3。对话上下文携带情绪连续性，关键事件以自然语言记忆笔记补充。
6. **token 不怕多，回复不怕慢。** 真实性是唯一优先级。

---

## 架构总览

```
用户消息到达
  → 调度器：Lykie 现在"在线"吗？
    → 不在线（睡觉/上课）：消息进队列，不调模型
    → 在线：进入处理
  → 构建上下文（身份核 + 档案全文 + 状态 + 对话历史 + 记忆笔记）
  → 单次模型调用：回复，或 [不回复]
  → 回复 → 延迟发送（3-60 秒，模拟打字）
  → [不回复] → 消息留在队列等下次，或自然丢弃

后台调度器（常驻线程）：
  → 定时检查：Lykie 该主动说话吗？
  → 触发条件满足 → 构建上下文 → 单次模型调用 → 主动发送
```

## 规格 A · 核心管道（替代 think→lookup→speak）

### A.1 新模块 `lykie/converse.py`（替代 think.py + lookup.py 的入口角色）

```python
def build_messages(state, user_text) -> list[dict]:
    """单次调用：全量上下文 → messages。"""

def handle_message(state, user_text) -> dict:
    """主入口：返回 {reply, silent, delay} 或 {silent, queued}。"""
```

`build_messages` 注入顺序：

1. **身份核**（`lykie/prompt_core.txt` 精简版，≤20 行，从 self.txt 提炼的核心约束：你是 Lykie、口语短句、不认程序、多句分行、该不回就不回）
2. **人生档案全文**（`self.txt` 143 行原样注入，这是她"知道的事"）
3. **当前状态**：真实时间（`format_now_block`）、在干嘛（按课表/夜间/空闲判断）、心情倾向（从记忆笔记提取，如"最近和他吵过架，还有点别扭"）
4. **关系层**：当前是哪层 + 该层许可（STAGE_BRIEFS 对应层的 1-2 句话，不注入全部五层）
5. **记忆笔记**：关键事件的自然语言记录（见规格 C）
6. **最近对话**：最近 N 轮原文（N=30），带情绪连续性
7. **本轮用户消息**

模型直接输出回复文本或 `[不回复]`。

### A.2 system prompt 拼接示意

```
【你是谁】
（身份核 20 行）

【你的人生】
（self.txt 全文 143 行）

【现在】
现在是 2026年10月10日 周五 14:32。下午没课。
（记忆笔记：最近两天没和他聊，上一次他说考研压力大，你安慰了两句。）

【你和这个人】
认识但不熟悉。话不多，有防备。这层可以聊校园日常，不主动说私事。

【你记得的关于他的事】
（记忆笔记：他叫 LiZF，在准备考研。前天问了你一道操作系统题，你讲了。）

【最近对话】
user: 最近压力大
assistant: 嗯，考研确实熬人
user: 你那边怎么样

【本轮】
user: 你那边怎么样
```

模型输出：`还行，刚下课\n你呢，最近怎么样` — 完。

### A.3 与现有代码的对比

| 现有三段式 | 新单次调用 |
|---|---|
| think.py 输出 JSON（action/need/why + 6 字段） | 不存在中间产物 |
| clamp_decision 125 行改写模型决策 | 模型自己决定 |
| lookup.py 按 need 查课表/题面/档案 | 档案全注入，模型自己"回忆" |
| speak 拼 12 层规则 + 尾部 6 条杂规则 | 身份核 + 档案 + 状态 + 对话 |
| ACTION_LINES 注入 action 行为约束 | 保留概念但精简为身份核内一句话 |

## 规格 B · 调度层

### B.1 在线判断

```python
def lykie_status(now: datetime) -> str:
    """返回 'sleep' | 'class' | 'free' | 'study' | 'late'"""
```

- `sleep`：23:00-07:00（可调），不处理消息
- `class`：按 self.txt 课表对应时段，不处理消息
- `study`：晚上写作业时段（如 20:00-23:00），可处理但延迟长
- `free`：白天无课、周末，正常处理
- `late`：很晚但还没睡（如 22:00-23:00），可处理但可能不回

### B.2 消息队列

- 不在线时消息进队列（`data/users/<用户>/pending.json`）
- 醒来/下课后处理队列：
  - 有 1 条：正常回复，可能带"刚睡醒/刚下课，没看见"
  - 有多条：合并处理，不是逐条回——模型看完全部消息再决定怎么回
  - 隔了很久（如过夜）：可能主动先发一条"昨天睡了你那边怎么样"

### B.3 回复延迟

- 在线 `free`：3-15 秒
- 在线 `study`：30-120 秒
- 在线 `late`：可能不回（留到明天）
- 刚醒来处理队列：10-60 秒（"刚看见"）

延迟用后台线程 + `time.sleep` 实现，不阻塞 HTTP 响应。前端轮询或 WebSocket 获取回复。

### B.4 技术实现

- 后台调度线程：`threading.Thread(daemon=True)`，每 60 秒检查一次
- 不引入新依赖（不用 Celery/Redis/APScheduler）
- waitress 单进程兼容（线程在进程内跑）

## 规格 C · 记忆设计

### C.1 短期记忆（对话历史）

最近 N=30 轮原文注入。真人也只记得最近的事，太久远的模糊。

### C.2 长期记忆（关键事件笔记）

**存储格式**：自然语言句子列表，存在 `data/users/<用户>/memories.json`

```json
[
  {"time": "2026-10-08", "text": "他第一次问你操作系统题，你讲了进程状态转换。他夸你讲得清楚。"},
  {"time": "2026-10-09", "text": "他说考研压力大，你安慰了几句。他没再说更多。"},
  {"time": "2026-10-09", "text": "他骂了你复读的事，你顶了回去。他没道歉。你现在还有点生气。"}
]
```

**提取机制**：对话结束后（或每 N 轮），用模型提取关键事件——不是 offense_count，是"发生了什么"的自然语言记录。复用 `extract.py` 的调用模式，改 prompt 为"用一两句话记录本轮发生的值得记住的事，没有就空"。

**注入**：全部笔记注入上下文（每条 1-2 句，30 条也就几百字，不会撑爆上下文）。

### C.3 人设记忆

self.txt 全量注入，每轮都带。这就是她"知道的事"——课表、性格、害怕、喜欢、出身（作者层部分她自己不知道，注入时标注"以下是她不知道的"或分段处理）。

### C.4 废除的机制

| 废除 | 替代 |
|---|---|
| `portrait.offense_count` | 记忆笔记："他骂了你复读的事，你顶了回去" |
| `portrait.unapologized` | 记忆笔记："他没道歉，你还有点生气" |
| `portrait.warned` | 记忆笔记 |
| `clamp_decision` 125 行 | 模型自己判断 |
| `THINK_SYSTEM` + JSON 输出 | 不存在 |
| `lookup.run_lookup` 查课表 | 课表在 self.txt 里，模型自己看 |
| `ACTION_LINES` 7 行为约束 | 精简后并入身份核（"不熟就冷一点、被冒犯要顶回去、不想聊就不回"） |
| `facts` 结构化事实 | 记忆笔记（"他叫 LiZF，在准备考研"） |
| `style_notes`（口吻规则列表） | 说话范例库 + 教过的记忆（见规格 G） |
| `corrections`（监督案例注入） | 教过的记忆（见规格 G） |
| 👍👎 驱动 `clamp_decision` | 删除（clamp_decision 已删） |

### C.5 关系层进展

- 五层概念保留（开局→认识→能说事→能谈心→情侣）
- 层级许可注入上下文（"你现在和他认识但不熟悉"），模型据此调节语气
- 层级进展**不放权给模型自动判断**——由作者手动调整，避免模型自作主张升温
- 不再用 `clamp_decision` 硬关 teach：模型看到"认识层、有防备"自然不会主动讲题；看到"能说事"自然愿意教

## 规格 D · 主动消息

### D.1 触发条件

| 条件 | 主动说什么 |
|---|---|
| 刚醒来 + 昨晚有未读 | "昨天睡了没看见，你那边怎么样" |
| 刚醒来 + 昨晚没消息但关系到"能说事" | "早，今天没课，在发呆" |
| 刚下课 | "刚下课，累死了" 或（有题时）"刚才那道题你试了没" |
| 遇到什么事（低概率随机触发） | "问个事，你们那边……" |
| 关系到"能谈心" + 一天没聊 | "今天怎么样" |

### D.2 实现

后台调度线程每 60 秒检查触发条件。触发时构建上下文（和被动回复相同的 `build_messages`，但 user 消息为空或为"你想主动跟他说点什么"），模型输出消息文本，主动发送。

### D.3 频率控制

- 主动消息每天最多 2-3 条
- 同一条件 24 小时内不重复触发
- 关系层越低频率越低（认识层几乎不主动）

## 规格 F · 作者监督（"父母教孩子"模式）

### F.1 设计理念

作者不是在写规则手册，而是在"教女儿说话"。监督产物不是"必须遵守的规则"，而是"我记得上次教过她什么"——自然语言记忆，模型读起来像回忆，不像背规矩。

### F.2 两个产物

| 机制 | 存什么 | 存在哪 | 怎么注入 |
|---|---|---|---|
| **说话范例库**（静态大库） | "他说 X，你说 Y"的范例 | `data/lykie_shared.json` 的 `examples` 字段 | 按当前用户消息关键词匹配，每轮注入 ≤5 条；匹配不到不注入 |
| **教过的记忆**（动态） | "上次你说 X，我告诉你 Y 更好" | `data/lykie_shared.json` 的 `taught` 字段 | 每轮全量注入（自然语言，几十条几百字） |

### F.3 说话范例库

**格式**：

```json
[
  {
    "trigger": "谢谢",
    "context": "他说'谢谢'",
    "lykie_said": "谢什么谢",
    "note": "不客气，带点傲娇"
  }
]
```

**检索方式**：关键词匹配。用户消息中包含范例的 `trigger` 关键词时，命中该范例。

- 匹配逻辑：用户消息分词后与 `trigger` 做子串匹配
- 取命中范例的前 5 条注入
- 无命中时不注入（模型"裸奔"也比读 100 条范例好）
- 先从最简单的子串匹配开始，效果不好再加同义词/分词

**注入格式**（system prompt 内）：

```
【你说话的范例（学语气，不是背台词）】
他说：谢谢
你说：谢什么谢
（不客气，带点傲娇）
```

**入库方式**：作者通过管理界面或直接编辑 JSON 添加。不经过模型，不自动提取。

### F.4 教过的记忆

**触发方式**：作者发送 `纠正：xxx` 消息时，进入"教她"模式。

**流程**：

1. 作者发 `纠正：你这话说得太客气了` → 系统识别为纠正指令
2. 模型收到："用户觉得你刚才说'不用谢'太客气了。Lykie 不会这么客气，可以'谢什么谢'。简短表示记住了。"
3. 沉淀一条教过的记忆：

```json
{
  "time": "2026-10-10",
  "context": "他说'谢谢'，你说'不用谢'",
  "taught": "别说'不用谢'，太客套。可以'谢什么谢'",
  "why": "Lykie 不客气，带点傲娇"
}
```

4. 同时可选入库为说话范例（trigger="谢谢"）——作者在纠正时可选"存为例例"

**注入格式**（system prompt 内）：

```
【你教过她的事（记得感觉，不是背规则）】
- 他说"谢谢"时你说"不用谢"——太客套了。可以"谢什么谢"。（Lykie 不客气，带点傲娇）
```

**容量控制**：上限 100 条（每条 1-2 句，100 条约几百字，不会撑爆上下文）。超限删最早的。

### F.5 废除的监督机制

| 废除 | 理由 |
|---|---|
| `style_notes`（口吻规则列表，上限 30 条） | 规则式注入导致模型收敛，改用教过的记忆 |
| `corrections`（监督案例，上限 25 条取 6 注入） | 同上 |
| 👍 按钮（点赞） | 不再需要程序驱动的评价 |
| 👎 按钮（点踩） | 改为 `纠正：xxx` 指令，走教过的记忆流程 |
| `add_style_notes()` / `add_correction()` / `style_notes_summary()` / `corrections_summary()` | 随机制废除 |

### F.6 落地时机

- **第一步（单次调用替代三段式）**：**监督产物全部不注入**。让模型只吃身份核 + self.txt + 对话历史 + 记忆笔记，看"裸奔"效果。验证"规则少了之后模型会不会正常思考"。
- **第二步（效果稳定后）**：加回教过的记忆（从 0 条开始攒）。
- **第三步**：加说话范例库 + 关键词检索。
- 不在同一批做——每步独立验收，确认效果再加下一层。

## 规格 G · "把题交给她"

现有机制保留：题卡按钮挂待发块 → 用户送出后变成 user 消息 → Lykie 正常处理。她看到题面是"对话里有一条用户消息说这道题"，不是程序额外注入。她愿不愿意讲、怎么讲，由模型根据关系层和上下文自己判断。

## 分步实施

### 第一步：单次调用替代三段式（影响最大、风险最高）

- 新增 `converse.py`，实现 `build_messages` + `handle_message`
- 改 `app.py` 对话路由调用 `converse.handle_message`
- 删 `think.py`、`lookup.py` 查询逻辑、`clamp_decision`
- **监督产物全部不注入**（style_notes / corrections / 范例库 / 教过的记忆）——让模型只吃身份核 + self.txt + 对话历史 + 关系层，看"裸奔"效果
- 暂不加调度层——先验证"单次调用 + 最少规则"效果是否比三段式好
- 验收：对话 10 轮，判断"像不像真人在说话"，重点看模型是否会自己判断该不该回、怎么回

### 第二步：记忆笔记

- 新增 `memories.py`
- 改 `extract.py` 提取自然语言事件
- 删 portrait 计数器
- 验收：跨天对话仍记得"昨天聊了什么"

## 验收（终极目标）

- [ ] 你和 Lykie 微信式聊一周，不被识破是 AI
- [ ] 夜里发消息无即时回复，白天收到回复带"没看见"
- [ ] 她会主动找你说话（下课、醒来、关系到了某层）
- [ ] 被骂后她会顶回去，后续对话带着情绪，不是"下一条消息就忘了"
- [ ] 讲不讲题由她自己判断，不是程序硬关
- [ ] self.txt 全文每轮注入，不丢任何档案

## 边界

- self.txt、人设、开场剧情、监督机制：不可改
- 刷题/进题/简答/模考/错题：与对话架构无关，不动
- 不引入新依赖
- 不用模型做"思考中间步"——模型只在对话时调用一次
- 主动消息频率不失控（每天上限、同条件不重复）
