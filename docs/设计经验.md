# 设计经验

做功能前先过一遍本文件，避免重复踩已踩过的坑。新经验由作者拍板后追加。

## 1. 大段机器产物不做「预览审查」

- **经验**：导入/解析类功能中，把机器生成的全文预览（如整卷分段预览）摆给用户"审查"，是无效 UI。文本一长没人会逐字看，预览沦为摆设，还占页面、拖慢录入。
- **做法**：审查点要么压缩成一行关键指标（如"共 N 段"），要么直接信任管道，把问题留到结果页（阅读视图）里修，不在中间环节设审查关卡。
- **出处**：2026-10-31，导入英语试卷实测。分段预览全量渲染无人看，已删除；同思路下 `/api/reading/preview` 端点一并移除。

## 2. 表单默认值自动带入，用户只做修改

- **经验**：能从上下文自动得到的默认值（如 PDF 文件名 → 试卷名称），应自动填入，让用户从"改"开始而不是从零输入。
- **做法**：默认值带入后保持可改；用户已手动编辑过的字段不被后续自动操作覆盖。
- **出处**：2026-10-31，导入英语试卷。上传 PDF 后名称框自动填入文件名（去扩展名），允许修改。
