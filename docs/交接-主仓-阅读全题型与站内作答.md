# 交接-主仓-阅读全题型与站内作答

## 需求与拍板链（2026-10-15/16）

- 整卷 PDF 直接导入，自动识别题型、拆分阅读与题目。
- 本期范围：CET 阅读三节——Section A 选词填空 / Section B 长篇阅读（段落匹配）/ Section C 仔细阅读。
- 选词填空把候选词区（词库）当题目。
- 站内做题：选项可点选、判正误；**不要点击就出答案**，由用户自己选择时机对答案。
- 对答案放在答题卡（题卡）：每题可单独对答案，也可做完统一对答案。
- 标准答案双通道：用户自行导入 + 站内 DeepSeek 生成（AI 答案仅供参考）。
- AI 出答案只出字母不生成解析；解析需求由用户用既有站内 AI（题目区划词查词/翻译）自行提问，**本期不加"问 AI"按钮**。
- 听力/作文/翻译：要做，优先级低，放后面（见备忘区）。

## 真题行样实测（依据：2026-06 第 1 套，pypdf 6.20.0 提取）

| 要素 | 实测行样 | 结论 |
|---|---|---|
| 卷面结构 | Part I 写作 / II 听力 / **III 阅读** / IV 翻译 | 阅读节号不固定，裁剪认 `Reading Comprehension` 关键词，不写死节号 |
| Directions | `Directions: In this section, ...` 英文长段 | 段首识别整段丢弃 |
| A 节正文 | 空格以裸数字内嵌（`the capitalists 26 every ounce`） | 正文原样保留，不加高亮 |
| 词库 | `A) available I) increased` 一行两词，`H) experience` 单词行，A-O 共 15 词 | 新词库正则（1-2 词条/行）；现有 A-F 选项正则会漏 |
| B 节段落 | `A) I was glad I had such terrible jetlag. ...` 长段，**与选项行同形** | 切分必须节感知，否则 B 节正文被当选项吸进题目 |
| B 节题目 | `36. 陈述句`，无选项行，答案=段落字母 | 每题一卡，选项=检测到的段落字母 |
| C 节 | `46. 题干` + `A) B) C) D)` 选项，两篇 Passage | 沿用现行逻辑，选项结构化 |
| 页脚 | `2026 年 6 月大学英语四级考试真题(第 1 套) 3` | 现有 `_FOOTER_RE` 覆盖，回归验证 |

## 数据模型（readings.json 该 text 记录扩展）

```json
{
  "answer_key": {"26": "N", "36": "F", "46": "B"},
  "answer_key_source": "user" | "ai",
  "answers": {"26": "B", "36": "F"},
  "judged": {"26": true, "36": true}
}
```

- `answer_key`：题号→答案字母；导入/AI 生成时整体覆盖，导入覆盖 AI。
- `answers`：用户选择，即选即存（刷新不丢）。
- `judged`：已判题锁定（不可改选），「重做」清空 `answers`+`judged`。

## 后端

### lykie/readings.py

1. `extract_pdf(file)`：pypdf 逐页提取文本；提取失败/无文本层（扫描版）→ 明确中文错误。
2. `slice_reading_part(text)`：定位 `Reading Comprehension` Part 到下一 Part；命中→裁剪；未命中→原样返回全文（`sliced: false`，用户预览时自行删）。
3. 切分器升级为**节感知状态机**：按 Section A/B/C 标记分节，各节各规则；Directions 段首整段丢弃；节内逻辑：
   - **A 节**：正文=无标记长段；词库区=尾部短行选项模式（解析 `([A-O])\)\s*(\S+)`，1-2 词条/行，凑满 15 词校验）；题目=正文句中裸数字 26-35，每空一题，`kind:"bank"`，题干=含该数字的句子（句界沿用 .!?+引号收尾规则），选项=词库 15 词。
   - **B 节**：正文=字母开头长段（`A) ...`，原样保留字母前缀，比对答案需要）；题目=首个题号起至节尾的题号段，`kind:"match"`，选项=检测到的段落字母（A-J…按实际段数）。
   - **C 节**：沿用现行逻辑，`kind:"choice"`，选项结构化 `{key, text}`。
   - **无 Section 标记**→legacy 路径，现行 `split_questions` 原样（老子篇零回归）。
4. `parse_answer_key(text)`：宽松解析——`36-45 FBAID` 连写、逐行 `36. F` / `36 F`、混排都认；解析失败原样报错不存。
5. `split_questions` 返回结构化题目：`{num, stem, options:[{key,text}], kind}`；渲染层每次读文时计算（readings.json 只存全文，沿现行惯例）。
6. text 记录读写：`answer_key/answers/judged` 的存取辅助函数。

### app.py（6 新路由，均登录态）

| 路由 | 作用 |
|---|---|
| `POST /api/reading/pdf` | 上传 PDF→提取→裁剪→返回预览文本（不落库，前端填入导入框走既有预览管道） |
| `POST /api/reading/<id>/answer` | 存单题选择 `{num, key}`；已判题拒绝 |
| `POST /api/reading/<id>/judge` | `{num}` 单题判；`num` 缺省=统一判**所有已作答题**（未作答不判不锁） |
| `POST /api/reading/<id>/answer_key/import` | 用户粘答案→`parse_answer_key`→存 `source:"user"` |
| `POST /api/reading/<id>/answer_key/ai` | DeepSeek 生成：正文+题目+词库入 prompt，json_mode 温度 0，只输出 `{题号:字母}`；复用 `_parse_llm_json` 降级；存 `source:"ai"` |
| `POST /api/reading/<id>/reset` | 清 `answers`+`judged`（答案键保留） |

## 前端（reading v10）

1. **导入**：reading.html 导入表单加 PDF 上传；选文件→POST `/api/reading/pdf`→回填文本框→触发既有分段预览。
2. **题卡作答**：选项渲染为可点按钮（bank=15 词、match=字母行、choice=4 项）；点选=选中态+即存 `/answer`；未判可改选，已判锁定。
3. **对答案**：每张题卡（单题卡+全部列表内每题）配「对答案」小按钮，已选才可用，点击仅判该题——错选红、正确答案高亮绿、该题锁定；「全部」列表顶部「统一对答案」按钮一次判完已作答题。无答案键时对答案按钮禁用。
4. **重做**：题卡区「重做」清空全部作答与判分态。
5. **答案入口**：阅读页顶栏「导入答案」（粘文本）与「AI 出答案」两入口；AI 生成后 UI 标注「AI 生成，仅供参考」；导入可覆盖 AI。
6. 划词查词在新选项 UI 内照常工作（选项是文本，mouseup 管道不动）。

## 定案与取舍

- **判分粒度**：judged 为逐题状态；统一对答案只判已作答题，未作答保持可做——部分作答不被锁死。
- **AI 答案定位**：兜底不是权威；DeepSeek 四级阅读偶有做错，误判会"冤枉"用户，故来源标注不可省，用户导入随时覆盖。
- **A 节题干**=含空格数字的原句，翻卡即见语境；正文内嵌裸数字不做视觉高亮（易误伤年份/数据，收益低）。
- **作答落点**：内嵌该篇 readings 记录，不进错题本、不推题库——阅读作答与题库管道暂不打通。
- **节/篇章标记行**（Section/Passage/Questions to）：结构信号，渲染层不显示。

## 验收标准

1. 仓库 8 份真题 PDF 逐份：整卷上传→自动裁出阅读三节→解析正确（A 节 10 空+15 词库、B 节 10 题、C 节 10 题×4 选项；2025-12 套如有题型偏差如实记录处理）。
2. 老子篇（无 Section 标记）零回归：读/查词/标记/悬浮球全部照旧。
3. 作答→刷新不丢；单题对答案只影响该题；统一对答案判完已作答；重做清空。
4. 答案键三格式（连写/逐行/混排）可解析；AI 答案带「仅供参考」标注；导入覆盖 AI。
5. 无答案键：可读可作答，对答案禁用。
6. 服务器缺 pypdf 时 PDF 上传给明确中文提示；扫描版 PDF 报错不崩。
7. 划词查词/例句同步在题卡选项区照常。

## 风险与边界

- B 节段落/选项/词库三者同形 `A)`，节感知切分是最大技术风险——8 份 PDF fixture 回归兜底。
- 判分依赖题号稳定；用户手改正文导致题号错位时答案会错位（预览可修，可接受）。
- 服务器部署后需 `pip install pypdf` 一次（本机 6.20.0 已验证）。
- AI 生成单次调用携带全文（约 1.7 万字符），BYOK 成本用户自担。

## 备忘区（本次不做）

- **听力/作文/翻译**：用户明确要做，优先级低。听力需音频方案、翻译为中文段、作文待定形态，规格未议。
- 阅读作答 ↔ 错题本/题库管道打通：未议。

### 测试抓出并修复的真 bug（按发现顺序）

1. **已判锁定失效**：judged=False（答错）时字符串比对不命中，答错题不锁仍可改选——判过的题无论对错都应锁定，改 `num in judged`。
2. **导入答案不闭环**：后端不回 key 明细，前端本地 answer_key 不更新，「对答案」按钮解不了禁——两个 answer_key 路由返回 key。
3. **Section 标记被自吞**：渲染层清洗把 Section 行当 Marker 过滤，`_split_sections` 看不到分节信号，全套卷退化 legacy——清洗只能放在分节之后（`_split_sections` 必须吃原始段落）。
4. **智能引号切句失败**：PDF 提取出 `“”` 智能引号，句切分正则只认直引号，`。”` 切不开、两句合并后每句只认第一个空格数字，后续空格全丢——字符类补智能引号。
5. **词库块归错节**：2024 套 PDF 文本流把 Section B 标记排在词库区之前，词库行进了 B 节，A 节无词库——词库特征极强（A-O 单词短行），改全局 `_extract_bank_block` 摘除后传给 A 节（连续纯词条短行 ≥10 才认）。
6. **空格数字双正则**：`___33___`（2025 套下划线形式）与 `for 29 40,000 words`（后跟数量词）、`20,000 ___33___`（前是数量词）三种卷面形式无法用单正则统一——宽 lookbehind 会让 20,000 的尾 0 吞掉 `___` 导致 33 永不命中，拆成两个正则：下划线包裹直接收 + 空格包裹窄 lookbehind 宽 lookahead（26-55 区间过滤误伤）。
7. **B 节相邻段合并**：2026-06-1 的 F/G/H/I 四段被 normalize 短行启发合并成 2030 字符巨段，match 选项只剩 8 个字母——行首「字母+括号起新段」规则从 A-F 扩到 A-O（B 节段落标记与 C 节选项同形，词库行中段词条不受行首规则影响）。

### 验证（27 case 全过）

8 份真题 PDF 全管道（每套 A10 空+15 词库 / B10 题+段落字母 11-15（卷面干扰段差异）/ C10 题×4 选项）、老子篇 legacy 零回归（纯段落渲染、无 options 字段）、C 节选项结构化+Directions 丢弃、答案三格式解析+垃圾输入报错、作答→锁定→重做→重判全链路、统一判分只判已作答、AI/user 答案键切换（ai 标注可被 user 覆盖）。

### 已知边界

- match 段落字母选项数为实际检测到的段落数（11-15），卷面正文段天然多于题数（干扰段），非 bug。
- A 节题干取含空格数字的原句，句子切分按句号+智能引号粗切，极端无标点长句会整句做 stem（可读，无功能影响）。
- AI 出答案真实 DeepSeek 调用未离线验证（LLM 层复用查词管道已验机制，monkeypatch 未烧 Key）——待用户本地实测。
- 服务器部署需 `pip install pypdf`（缺失时 PDF 上传给中文提示不崩，复制粘贴导入不受影响）。

## v12 修正记录（2026-10-16 用户三条实测反馈）

1. **tab 点击无反应（长篇/篇章 Two/Three 全部死按钮）**：根因——tab 渲染在 `#rdTabs`（qBody 的兄弟节点），但点击处理绑在 qBody 的监听器里，点击永远到不了。修：tab 点击处理改绑 tabsEl。
2. **选词后空块不突出**：is-picked 原来只变色太弱，强化为 1.5px 实线主题色边框 + 主题色底 + 粗体。另有隐性 bug：空块二次渲染从已被改写的 textContent 重建，改选/判分后状态过期（首次选词靠侥幸更新）。修：段落原文存 `data-orig`，每次从原文幂等重建。
