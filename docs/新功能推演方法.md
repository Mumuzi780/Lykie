# 新功能推演方法

做任何新功能（新题型、新练习模式、新交互）之前，先过一遍本文件，按此思路完成推演，再写规格、再动手。推演必须在实际执行前完成，而不是先上线第一版再迭代——纸上推演的成本远低于线上返工。

## 核心原则

1. **先做加法，再做特色**：第一步永远是把新内容原封不动、零设计地搬上网站（能导入、能看到、能作答）。这一步推演是完备的，不需要发挥。特色修改是第二步，且必须建立在第一步推演完成的基础上。
2. **推演小白用户的完整痛苦链路**：特色修改不是拍脑袋想"加什么功能"，而是想象一个小白用户从头到尾做一遍，把每一个卡点找出来。卡点找穷尽了，特色修改自然浮出来。
3. **区分要消除的痛苦和要保留的挣扎**：卡住后放弃的痛苦要消除（这是流失根源）；但"想不起来"的那几秒挣扎要保留——学习恰恰发生在那里，直接给答案会杀死学习时刻，也让掌握错觉无法显影。
4. **卡点必须沉淀为数据**：做完即丢等于白做。用户卡过的点、用错的点要落入资产库一类的持久结构，几篇做下来形成"残余缺口显影"——这是网站相对纸卷的本质优势，每个新功能都要问一句：这个功能产生的学习痕迹落在哪。

## 推演步骤

### 第一步：零特色搬运

- 问题只有"源文件里的内容如何完整、不错位地进网站"，复用现有导入管道，不做任何新交互。
- 验收标准：内容完整、不粘连、不错位，存量数据刷新即可见。

### 第二步：小白走查（特色修改的来源）

按用户真实使用的时间顺序逐环节过，每个环节问三个问题：

1. **用户会卡在哪？** —— 找出所有卡点，一个都不要漏。
2. **卡点属于哪种类型？** —— 类型决定引导方式。以翻译题为例：
   - 完全不会（连词都不认识）→ 只能给，但给之前先让他试
   - 提笔忘词（认识但写不出）→ 阶梯提示：首字母+词长 → 中文语境 → 完整答案，每阶都让用户先自己试
   - 搭配不会（单词都会但拼不成块）→ 给词块而不是给单词
3. **这个痛苦要消除还是保留？** —— 用原则 3 判断。

### 第三步：排序与分期

- 核心理念所在的卡点（如翻译的无痛引导）做精，是功能的灵魂。
- 实现成本极低、体验改善大的（如逐句呈现降低整段压力）跟着第一批做。
- 依赖 AI 批改或数据积累的后置（先手动对答案，批改后上）。
- 交互形态没经过真人试用的，宁可先做最轻版本，跑通后再定规格（同简答训练纪律：未经作者本人试用确认的细则，不当成已定规格开发）。

## 首个案例：四级翻译题（2026-11-17 推演）

**第一步**：翻译区从整卷 PDF 原封不动导入答题区，复用阅读解析管道。

**第二步小白走查，卡点清单**：

| 卡点 | 类型 | 处理 |
|---|---|---|
| 词块不会翻（"政策""截至2025年"） | 完全不会 / 提笔忘词 / 搭配不会三态 | 阶梯提示，不给直接答案（核心理念，优先做） |
| 整句不知从哪下笔 | 主干缺失 | 主干模板提示（`____ has improved ____`），按需出现，不做成独立题型 |
| 整段压力导致弃疗 | 压力过大 | 逐句推进，一次只呈现一句，对答案时再合并整段 |
| 对答案满篇红，感觉"全错了" | 挫败 | AI 批改逐句对齐，先说翻得好的，再逐句讲偏在哪 |
| 做完即丢 | 无沉淀 | 卡过/用错的词块一键录资产库，例句自动带参考译文原句 |

**第三步排序**：阶梯提示+逐句推进第一批；AI 逐句批改、卡点沉淀依赖批改后置；主干模板等真人试用后再定形态。

## 维护

新功能推演时按本文件走一遍；推演产出（卡点清单、排序结论）记录在该功能的交接文档或本文件追加案例，由作者拍板后收录。
