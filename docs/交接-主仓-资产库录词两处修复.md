## 问题一：固定短语无法作为整体录入

**现象**：take to heart 这类固定短语要录成独立词头，但表单强制至少选一个词性，没有「固定短语」入口。

**现状事实**：
- 后端 `POS_OPTIONS` 已含 `"phr."`（`lykie/assets.py` L15），数据模型天然支持多词词头（`normalize_word` 按空白折叠，无障碍）。
- 缺口纯在交互层：`static/assets.js` 词性 pill 强制至少选一个（「至少保留一个词性」）。

### 方案（A 推荐）

**A. 前端加「固定短语」开关**（推荐）
- 单词输入框旁加 toggle（如 checkbox「固定短语」）。
- 开启后：隐藏词性 pill 区；渲染**单个**「固定短语」义项块（释义 / 例句 / 来源，保留同句再录按钮）。
- 提交时该块映射为 `senses: [{pos: "phr.", meaning, examples, source}]`。数据模型零改动。
- 交互细节：同句再录带入时保持开关状态；每次成功保存后开关重置为关（与现有表单清理一致）。

**B. 新增 entry `kind` 字段区分短语/单词**：改动面大（序列化 / 列表 / 搜索 / 合并全动），收益仅语义更纯。不推荐。

**取舍**：模型层 `phr.` 已够用；A 的改动集中在一个文件。

## 问题二：PDF 复制粘贴的例句被拆成多条

**根因（已定位）**：
1. PDF 复制的文本带硬换行：`"…is unproductive and an\nexhausting way to go through life. || 讨好他人…"`
2. 后端 `_parse_examples`（`lykie/assets.py` L144-146）字符串分支按 `\n` 逐行拆，一行一例 → 一句变两条：前半句纯英文、后半句带中文。
3. 前端 `parseExampleField`（`static/assets.js` L158-167）只取**第一行** → 同句再录预填的是不完整前半句，并随 co_sents 边扩散到关联词条。

### 方案：软换行规则（单一规则，前后端一致）

- **单个换行 = 软换行**：例句内部以空格连接。
- **空行（连续换行）= 例句分隔符**：保留「一次贴多条例句」的既有能力。
- 单行 `英 || 中` 格式不受影响。

**改动点**：
1. `lykie/assets.py` `_parse_examples` 字符串分支：先按空行分块，块内各行以空格 join 成一条。
2. `static/assets.js` `parseExampleField`：同样按空行分块，取第一块、行以空格 join（同句再录预填到完整句）。

**不动的**：
- `_parse_related` 按行拆（旁系一词一行，语义正确）。
- `_parse_phrases` 字符串分支按行拆（短语一行一条，语义正确）。
- 短语例句走同一 `_parse_examples`，自动受益。
- 不做粘贴时即时合并显示（解析层统一处理，保持最小改动）。

## 第二轮修复（2026-10-12，已实施）

用户实测（修复一轮后）发现两个新问题，均已修复：

### 问题三：同句再录换词性后例句丢失

**根因**：旧实现把例句文本预填进默认 `n.` 的义项框，切换词性时槽位重建，例句随之丢失；且预填本身是多余交互——`link_example` 一直随提交静默传给后端。

**修复（横幅模式）**：
- 同句再录不再预填任何输入框；表单顶部显示只读横幅「同句再录 · 原句已带上」（两行截断，title 悬浮全文，带取消按钮）。
- 提交时 `attachPendingExample` 自动把原句（含来源）挂到**首个尚无例句的义项**；用户自贴的例句/来源不覆盖。
- `onFormCoSent`（表单上的同句再录按钮）链式续录时优先用横幅携带的原句，原句为空才要求表单贴例句——链不再断。
- 挂句目标固定为首个义项（多词性场景同旧版行为，已知局限）。

### 问题四：来源每次都要手输

**修复（粘性来源）**：
- localStorage 键 `assetsLastSource` 记住最近一次提交里首个非空来源。
- 新词/新义项槽/固定短语槽自动预填该来源（可见可改）；同句链式录词直接继承原句自带的来源。
- 提交成功即更新记忆；换一套真题时只需改一次。

### 改动文件

- `static/assets.js`：`stickySource`/`rememberSource`/`attachPendingExample`/`renderCoSentBanner`；重写 `startCoSentRecord`（横幅+来源预填）、`onFormCoSent`（链式例句优先级）、`onSubmit`/`onFormCoSent` 挂句+记来源；各义项槽预填粘性来源。
- `templates/assets.html`：`coSentBanner` 横幅元素；静态资源 bump v16。
- `static/assets.css`：横幅样式。
- 后端零改动（`link_example`、sense 级 source 均已有支持）。

### 验收（已过 node 行为测试）

- 同句再录后任意切词性/开关固定短语 → 原句始终由横幅携带，不丢。

- 来源只输一次，后续词自动带出；链式录词来源随原句继承。

## 第三轮修复（2026-10-12，已实施）

用户录入全卷后实测反馈的四个体验问题 + 一个功能优化，均已落地：

### 体验修复

1. **词性默认全不选**：初始/重置/同句再录空表单时 `selectedPoses = []`，用户点词性才出输入框；去掉「至少保留一个词性」限制，提交时校验「请至少点选一个词性（或勾选固定短语）」。
2. **同句再录隐藏例句框**：`renderSenseBlocks` 在 pendingLink 激活时不渲染例句 label/textarea（原句由横幅携带）；`syncSenseDraftFromDom` 对隐藏字段保留草稿原值不清空（保护用户已贴例句）。
3. **保留已输入内容**：`startCoSentRecord` 检测表单已有内容（word 或释义）→ 仅设 pending 状态、渲染横幅、补来源到空槽，不清任何输入；空表单才走完整重置。`onFormCoSent` 链式保存后显式清 word/草稿再续链。
4. **提交按钮横跳**：`.assets-col-capture .vocab-form` 改 `overflow-y: auto; overflow-x: hidden`——内容宽度临界时横向滚动条反复出现/消失导致按钮上下跳，横向裁掉即根治。

### 功能：库内例句自动同步（双向）

- **拉取**（`_sync_examples_from_lib`）：record_vocab 保存前，扫描本用户库中**其他非 stub 词条**（senses + phrases 的全部例句），英文句 word-boundary、大小写不敏感匹配当前词头（`(?<!\w)word(?!\w)`），命中例句合并进当前词条首义项（`_merge_examples` 去重、带来源），返回同步条数。纯本地确定性匹配，零模型调用。
- **推送**（`_push_examples_to_lib`，2026-10-13 补）：当前词条（senses + phrases）的全部例句，反向扫描其他非 stub 词条的词头，例句英文含该词头（同 word-boundary 规则）→ 例句并入目标词条**首义项**（去重、带来源），目标词条 updated_at 更新。与拉取合计为 synced 计数。场景：后录 ultimately 的例句含 embrace → 先录的 embrace 词条自动获得该例句，双向闭环。
- 保守边界：词形变化不匹配（desert ≠ deserted / embracing ≠ embrace）、自身不计、stub 不推不扫、去重幂等（重跑 0）；推送挂目标首义项（多义项词条可能语义错位，已知局限，词条作者自行把关）；推送不递归（单次 record_vocab 内拉取+推送各一遍）。
- `record_vocab` 返回 4 元组 `(entry, err, created, synced)`，app.py 透传 `synced_examples`；前端 onSubmit / onFormCoSent 成功提示追加「自动同步 N 条库内相关例句」。
- 存量数据不追溯，仅 record_vocab 时增量触发；补存量只需重录任一端（加深一次即触发，幂等）。
