# 翻译专项练习（/translate）

> 状态：**已定稿，待执行**
> 作者拍板（2026-11-17）：方案整体确认，含独立路由页入口、按卷分组列表、状态共享、润色编辑器、两步实施。

## 背景与定位

翻译题当前嵌在整卷阅读视图里（见 `交接-主仓-翻译题型一期.md`）。作者体验后发现：

1. 翻译与阅读答题模式不同，需要的屏幕空间也不同（整段润色要大编辑区），三栏布局下被挤压。
2. 整卷导入时翻译与阅读一体进来、答案一体生成，拆开不合适。

**结论：整卷翻译模式保留不动；新开专项练习模块，聚合所有已导入试卷的翻译题。**

### 三原则（作者已拍板）

1. **专项是视图，不是数据源**：不复制题目数据，直接引用 readings.json 各卷的翻译节（text_id 定位）。翻译题只有一个产地（整卷导入），复制会产生两份需同步的数据。
2. **答题状态共享，不隔离**：同一 storage key，整卷写过专项就显示已写，双向同步。"重翻练第二遍"是 attempt 维度，二期再议，现在不预设。
3. **整卷模式一行不动**：润色等新能力只活在专项里。

## 范围

### 第一步：列表页 + 练习页（逐句闭环平移）

**后端（唯一新端点）**

- `GET /api/translate/papers`：聚合当前用户所有 readings 中含翻译节的卷。返回按卷分组：
  ```json
  {"papers": [
    {"text_id": "…", "paper_title": "2024.06 第一套（来源）",
     "items": [
       {"key": "T", "preview": "近年来，……首句截断…", "sents": 4,
        "written": 2, "full_evaled": false}
     ]}
  ]}
  ```
  - paper_title 取 text.title（整卷导入时即为卷名）；一卷只有一个翻译节，items 恒为 1 项，但结构按数组留（未来一卷多篇翻译的卷型不破结构）。
  - written/full_evaled 从 get_translation 现算。
  - 放 `lykie/readings.py` 新函数 `list_translation_papers(username)`（读 + 聚合，纯本地）。

**前端（新文件，不动现有阅读前端）**

- `templates/translate.html`：独立路由 `/translate`，顶栏「翻译」按钮（登录态均可见）。布局：全宽限中（与 /import 同构），无三栏。
- 列表页：按卷分组卡片，每篇一行：首句预览 + `已写 n/m` 进度 + 评价状态（已整段评价 / 未），点击进入练习页（`/translate?text=<id>`）。
- 练习页：`static/translate.js`：
  - 左侧句列表（状态：未写 / 已写 / 已评），点击切换当前句；右侧大作答区（中文句 + textarea + 逐句 AI 评价区）。
  - 交互照搬整卷已验证模式：词块提示（v3 全局上下文版，含词块入库）、逐句 AI 评价、失焦静默保存、未写句按钮禁用 + input 事件解锁（v41 教训）。
  - **全部 API 复用现有 5 条路由**（GET translation / answer / hint / evaluate / evaluate full），零后端行为变更。
- 静态资源走独立版本号（translate.js v1），避免动 index.html 的阅读版本号。

### 第二步：润色编辑器（修法 2 落地，专项核心增量）

- 写完全部句 → 进入润色视图：**自动拼接稿预填大 textarea**，用户动手改衔接、统一术语、调语序（"整句组装"的练习环节）。
- 存储：`translation.polish = {"text": str, "base": str}`；`base` 为编辑时的拼接快照。
- 过期检测：任一句被改写 → 当前拼接 ≠ `base` → 润色稿标「基于旧版本」，提示重新润色；**不自动覆盖**用户改过的内容。
- **整段 AI 评价润色稿优先**：evaluate full 分支改为——有润色稿且未过期 → 评价润色稿；否则评价拼接稿。快照机制不变（润色稿改动同样触发重评）。
- 整卷模式终态**不显示润色稿**（整卷不动原则）。

## 实施顺序（给代码智能体）

1. `lykie/readings.py`：`list_translation_papers` + polish 存取函数（第二步可一并写入存储层，路由分步开）
2. `app.py`：`/translate` 页面路由 + `GET /api/translate/papers`
3. `templates/translate.html` + `static/translate.js` + 样式：列表页 + 练习页（第一步完成，可独立验收）
4. 润色编辑器 + evaluate full 润色稿优先（第二步）
5. index.html 顶栏入口 + script.js bump

## 验收标准

**第一步**
- 新导入含翻译的卷，`/translate` 列表自动出现，无任何同步操作
- 整卷写过 2 句 → 专项显示 2/5、续作定位第 3 句；专项写完 → 整卷终态直接可见（状态共享双向验证）
- 提示/评价/入库在专项页全链路可用，缓存与整卷互通（整卷点过提示，专项零模型调用）
- 整卷阅读视图回归零变化（现有 54 case 测试全过 + 页面手测）

**第二步**
- 润色稿编辑保存 → 改写任一句 → 「基于旧版本」提示出现
- 整段评价请求的评价对象为润色稿（服务端日志/测试断言确认）
- 整卷模式终态无润色展示

## 明确不做

- 不做翻译题独立导入（题目仍只从整卷 PDF 进）
- 不做重翻/attempt 版本管理（二期）
- 不做专项页问AI浮窗（逐句/整段评价已覆盖反馈职责）
- 不做整卷模式润色展示
- 列表页不做筛选/搜索（当前篇目量个位数）
