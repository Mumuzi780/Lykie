# 交接-主仓-阅读划词单词级吸附

状态：**已执行完毕**（2026-11-11，作者指令「按规格执行」）。
执行修订一处：原伪代码只看端点外侧紧邻字符，会把「选在标点上」的端点扩成整个相邻词（选 `", "` 吞进前词 `Hello`），与验收 6 矛盾；已修正为**边界两侧都是词字符**才算落在词内（本文二、三节为修正后定稿）。行为自测 10 case 全过，未提交 git。

## 一、需求与背景

现状：

- 双击、右键取词已经是单词级——`wordInfoAt()`（`static/reading.js`）以 `/[A-Za-z'-]/` 为字符集，向光标两侧扩到词边界后送入查词管道。
- 但**鼠标拖选**由浏览器按字符判定边界，可以从单词中间起、也可以在单词中间止。外显高亮和送进查词/翻译/标记的文本都可能是半截词（`art` 而不是 `article`）。

目标：松手后选区自动扩展到单词边界，外显选区以单词为单位，查词、翻译、标记自然沿用整词。不改动取词逻辑，不改后端。

## 二、交互与判定规则

1. 触发时机：`mouseup` 之后、弹出划词气泡之前，对当前选区做**一次性**词边界吸附。
2. 方向：**只向外扩，不向内缩**。「落在词内」= 边界**两侧**都是单词字符：
   - 起点：选区首字符与其左侧紧邻字符都是单词字符，说明起点在词中间，向左扩展到词首；
   - 终点：选区末字符与其右侧紧邻字符都是单词字符，说明终点在词中间，向右扩展到词尾；
   - 只看外侧紧邻字符是错的：选 `", "`（逗号起）会把前词整个吞进来，违反验收 6。
3. 单词字符集与 `wordInfoAt()` 完全一致：`/[A-Za-z'-]/`。中文、数字、标点、空格一律视为边界，不吸附。
4. 只在单个文本节点内扩展，不跨文本节点、不跨段落。跨越段落的拖选仍允许（查词可用），只是两端各自在本节点内补齐。
5. 选区为空（`collapsed`）不处理。
6. `anchorNode` 或 `focusNode` 不在阅读区（`inReadArea` 为假）不处理，避免误伤输入框、聊天浮窗、面板等区域。
7. 吸附后**不清除选区**，保留原生高亮——这就是「外显选区以单词为单位」。
8. 吸附后端点无变化时不做任何选区操作，避免无意义的选区重置与闪烁。

## 三、算法（伪代码）

```js
const CH = /[A-Za-z'-]/; // 必须与 wordInfoAt 内的字符集保持一致

function snapSelectionToWord() {
  const sel = window.getSelection();
  if (!sel || sel.isCollapsed || !sel.rangeCount) return;
  if (!inReadArea(sel.anchorNode) || !inReadArea(sel.focusNode)) return;

  const r = sel.getRangeAt(0);
  const sc = r.startContainer;
  const ec = r.endContainer;
  if (!sc || !ec || sc.nodeType !== 3 || ec.nodeType !== 3) return;

  const sv = sc.nodeValue;
  const ev = ec.nodeValue;
  let s = r.startOffset;
  let e = r.endOffset;

  if (s < sv.length && CH.test(sv[s]) && s > 0 && CH.test(sv[s - 1])) {
    while (s > 0 && CH.test(sv[s - 1])) s--;      // 起点在词中间：回退到词首
  }
  if (e > 0 && CH.test(ev[e - 1]) && e < ev.length && CH.test(ev[e])) {
    while (e < ev.length && CH.test(ev[e])) e++;  // 终点在词中间：推进到词尾
  }

  if (s === r.startOffset && e === r.endOffset) return;
  sel.setBaseAndExtent(sc, s, ec, e);
}
```

说明：

- 用 `setBaseAndExtent` 而不是 `removeAllRanges + addRange`，避免高亮闪一下再出现。
- `setBaseAndExtent` 会把 anchor 置为左端、focus 置为右端（正向化）。现有逻辑中只有 `isNoteableSelection()` 读取 anchor/focus（用于判定是否同段落），正向化不影响该判定；`positionOfSelection()`、`showBubble()`、`noteSegmentsOf()` 全部基于 range，与方向无关。
- 若个别浏览器上 `setBaseAndExtent` 后高亮不刷新，回退为 `sel.removeAllRanges(); sel.addRange(r);`（同样接受正向化）。
- 算法只做一次线性扫描，长度等于词长，无性能问题。

## 五、验收标准

1. 从 `article` 中间某个字母起拖到同词另一个字母，松手后高亮覆盖整个 `article`，气泡「查词」取到 `article`。
2. 从 `in the` 中 `the` 的 `h` 起拖到词外空格，松手后取 `the`。
3. 跨词拖选 `in the`，首尾补成整词，中间不变，仍按短语（`words` 计数）处理。
4. `don't`、`well-known` 内部起拖，不被 `'`、`-` 截断。
5. 反向拖选（从右往左）结果一致，无选区跳变、无丢字。
6. 起点或终点落在标点、空格上时不吸附，不吞标点、不扩到相邻词。
7. 选中后点「标记」，高亮覆盖整词；刷新页面后标记重放位置不漂移（`occur_index` 口径未变）。
8. 双击、右键查词行为与改动前完全一致。
9. 在输入框、聊天浮窗、悬浮卡片、面板内拖选文本，行为不受影响。
10. 手机端长按选词维持系统行为（本次不覆盖）。

## 六、边界与明确不做

- **不做拖动过程中的实时吸附**。在 `selectionchange` 里改写端点会让 Chrome 按鼠标位置重算选区、出现「回弹」跳动，反向拖选时锚点易漂移，移动端不可控。作者已确认接受松手吸附。
- **不做跨文本节点扩展**。正文被 `.rd-mark`、挖空等 `span` 拆开时词可能跨节点，第一版不补齐。已高亮的词整词在同一 `span` 内，触发概率低。
- **不改匹配口径**。`positionOfSelection()`、`wrapOccurrence()`、`extractSentence()` 仍用子串 `indexOf`，短词可能命中有更长单词内部的相同字母序列（如 `art` 命中 `article` 内部）。这是既有问题，与本次改动无关，另议。
- **不改移动端**。长按选词粒度由系统决定。
- **不做中文分词吸附**。

## 七、风险与兼容性

- 存量标记零影响：吸附只改变新选区的文本与 `occur_index`（同段文本内的计数方式不变），标记重放读取的是记录值。
- `info.words <= 5` 决定「查词 / 翻译」哪个是主按钮；吸附可能把半词补成整词，导致词数 +1，属于预期。
- 吸附后的 `extractSentence()` 用整词在段落文本中 `indexOf`，命中率只会升高，不会下降。
- 吸附后外显高亮可能含尾随空格（如 `don't `）——「只扩不缩」所致；`getSelectionInfo()` 已做 trim，查词/翻译/标记拿到的文本不带空格，无实际影响。
