# 交接规格：阅读并入主界面（多视图架构，消灭独立阅读页）

> 作者拍板（2026-10-16）：
> ① 主界面多视图——题库和试卷都在侧栏，点谁主区域显示谁，顶栏「阅读」按钮删除
> ② 试卷导入入口并进 /import 导入题目页
> ③ 不再支持导入普通文章——一律整卷导入；老子篇等既有普通文章保留兼容（可读可管理），但不再新增
> ④ 阅读视图顶栏按钮（导入答案/AI 出答案/重做）随视图进入 index 顶栏
>
> 本规格为定稿，执行按此文件；与旧文档冲突以本文件为准。
> 前置：试卷入题库侧栏（影子条目+归档）已实现（v16），本规格在其上重构。

## 定性

- index（`/`）成为唯一工作台：侧栏（题库+试卷+文件夹+归档）+ 主区域多视图（刷题卡片视图 / 阅读视图）。
- `/reading` 列表页、`/reading/<id>` 阅读页两个路由**废弃**（保留 301 兼容）。静态 reading.js 重构为「阅读视图模块」，由 index 按需激活。
- 数据层零改动：readings.py 的一切（卷检测/归档/作答/查词/标记/AI 答案）原样工作，改的是渲染宿主。

## 改动清单

### 1. 路由（app.py）

- `GET /`：读 `?read=<text_id>&sec=<key>`——有 read 参数时渲染 index 并注入阅读数据（text/sections/lookup_marks/answer_state + reading.css），主区域显示阅读视图；无 read 参数 = 现状刷题视图。
- `GET /reading` → 301 `/import`（试卷导入新家）。
- `GET /reading/<id>`（含 `?sec=`）→ 301 `/?read=<id>&sec=<key>`；`?paper=` toast 参数转 `&paper=`。
- `/reading/<id>/...` 下的 **API 路由全部保留不动**（answer/judge/reveal/answers/import/answers/ai/lookup/imported、paper/move|archive|restore）——前端 fetch 路径不变，零后端接口改动。
- index 的 `/api/banks` 等接口不动。

### 2. index.html（模板）

- 删除顶栏「阅读」按钮（`<a href="/reading">`）。
- `<main class="card-area">` 内新增 `<div id="readView" hidden>` 阅读容器：顶栏工具条（`RD_TOOLBAR`：导入答案/AI 出答案/重做，沿用现有按钮 id 与样式）+ `.reading-article` 分篇渲染区（由 reading.js 模块生成）+ 悬浮球/题目卡/弹层原 DOM。
- 引入 reading.css（v17）；reading.js 改为**按页面数据条件初始化**（body 带 `data-read-id` 时激活）；script.js 保留主导。
- 资源版本：script.js m98、style.css m97、reading.js/css v17。

### 3. reading.js 重构（核心工程，v17）

- **整个文件包 IIFE**，只暴露 `window.RD.init(hostEl, payload)`——解决与 script.js 的 `$`/`api`/`escapeHtml`/`post` 全局名冲突（script.js 的 `$` 是 getElementById 简写、api 带登录跳转，语义相同但实现有差；隔离后互不干扰）。
- 列表页逻辑（reading-page 分支）**删除**——列表页废弃。
- 阅读视图逻辑改为模块：init 时接收 payload（text/sections/marks/answer_state/textId），在 hostEl 内渲染分篇 + 初始化作答/查词/悬浮球。原 reading_view.html 中的静态 DOM（悬浮球/题卡/弹层）改为 JS 动态创建。
- 交互全保留：划词查词、查词卡、A 空块/B 徽章、悬浮球停靠/拖动、题卡 tab/缩放/滚轮隔离、AI 整理入口（资产页跳转链保留）、`?paper=` toast。
- `?sec=` 定位逻辑保留（init 后滚动+预选 tab）。
- 返回刷题视图 = 点侧栏任意题库条目（script.js 路由回 `/?bank=<id>` 刷题态）。

### 4. script.js（m98）

- 侧栏卷节条目点击：`history.pushState` → `/?read=<id>&sec=<key>` → 主区域切阅读视图。
  - 实现：拦截 makePaperLi 的 onclick（不再 location.href 整页跳转），`fetch('/api/reading/view/<id>')` 拿数据 → `RD.init()` 渲染。**刷题视图/阅读视图切换为纯前端态**，不整页刷新。
  - `popstate` 监听同步视图（后退回刷题态）。
- 刷题视图切换函数：隐藏 `#readView`、恢复 card-area 刷题 DOM、URL replaceState 去 read 参数。
- 顶栏「资产」按钮保留；`?back=/reading/<id>` 资产页返回通道改指 `/?read=<id>`（assets.js 一行）。

### 5. /import 导入题目页（试卷导入新家）

- 新增「试卷」分区：标题（建夹名）+ PDF 上传/粘贴 + 实时分段预览（preview API 复用）+ 提交 → `/api/reading/texts` → 成功后 `/?read=<id>&paper=<folder>` 展示 toast。
- 题库导入表单不动；两分区 Tab 或上下排（执行时按现有 import.html 结构最小改动）。

### 6. 资产页返回通道（assets.js）

- `backToReading` 白名单 `^/reading/` → `^/\?read=`（或直接构造 `/?read=<id>`），链接由 reading 视图携带。

### 7. 清理

- templates/reading.html、templates/reading_view.html 删除（路由已 301）。
- script.js 顶栏按钮引用、Lykie 面板对新视图的无感知（不动）。

## 明确不做

- 刷题视图、模考、错题本、Lykie 面板的任何改动（视图切换纯 DOM 显隐）
- 听力/作文/翻译节
- 普通文章的新增导入（老子篇等存量保留可读；列表页删除后入口=侧栏）
- 阅读视图内嵌「返回刷题」按钮（侧栏点题库即回）

## 验收标准

1. **视图切换**：侧栏点卷节条目 → 主区域变阅读视图（不整页跳转），URL=`/?read=<id>&sec=<key>`；点题库条目回刷题视图；浏览器后退/前进视图正确同步
2. **回归硬线**：刷题全链路（斩题/连击/错题本/模考入口/Lykie 面板/音效）在阅读视图进出后零回归——reading.js IIFE 后 `$`/`api` 冲突清零
3. **阅读功能全保留**：8 份真题 PDF 导入→侧栏→阅读视图：作答/判分/重选/看答案/查词/标记/悬浮球停靠/题卡缩放滚轮/AI 整理跳资产返回，逐项过
4. **导入**：/import 试卷分区可导整卷（PDF+粘贴）、自动建夹、toast 提示；顶栏无「阅读」按钮
5. **旧链接兼容**：`/reading/<id>` 301 新址、`/reading` 301 /import；资产页「←返回阅读」在多视图下工作
6. **老子篇**：侧栏未分类点入照常读+查词
7. **多账号**：read 参数访问他人卷 → 视图回退刷题态（后端守卫 404→前端回退）

## 风险与执行顺序

- 最大风险：reading.js IIFE 化的改造量（约 1500 行动全局隔离）+ script.js 视图切换态管理。**先做隔离骨架（IIFE+init 签名），再搬迁功能块，每搬一块跑一次刷题回归**。
- 顺序：app.py 路由 → index.html 容器 → reading.js IIFE 化 → script.js 视图切换 → /import 分区 → 清理删除 → 全量回归（node 冲突检查 + 浏览器实测清单）。

### 实测修正（2026-10-16 用户反馈，script.js m99 / reading.js v18）

1. **阅读态下点题库条目无响应**：题库条目点击只跑 loadBank，没接「退出阅读」——mode-reading 的 CSS 压制让刷题区全隐。修复：`#bankList` 委托监听，点非试卷条目（题库/模考合集）即 `showStudyView()` + replaceState 清 `?read`。试卷条目不在此列（本来就进阅读）
2. **点试卷节条目自动弹题卡**：`RD.init` sec 分支移除 `openCard()`——只滚动定位+预选 tab，球保持收起，用户自己点开
