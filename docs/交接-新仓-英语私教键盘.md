## 一、产品定位

一个自用安卓键盘：**打英文、发中文，中间由大模型批改指导**。

- 目的：在日常聊天中构造英语环境（写作端），不影响对方体验
- 接收侧不在本项目范围：微信官方「自动翻译收到的消息」已覆盖
- 本项目是学习站生态的手机端延伸（阶段二体现），但 MVP 零服务器依赖

### 目标用户

作者本人（四级备考中），自用不上架、不分发。

## 二、核心交互（已拍板，勿改）

### 双输入框模型

1. 键盘 UI 区域内自带一个**英文输入框**（EditText），用户在这里打英文
2. 点「译」→ 单次 LLM 调用 → **微信（或任意 App）输入框同步输出中文**
3. 英文原文**永不进入目标 App 的输入框**
4. 批改/润色/译文三合一结果展示在键盘自有区域

### 三合一结果展示

```
❶ 批改：you should to go → you should go（情态动词后接原形）
❷ 润色：I'm gonna head out now, ttyl
❸ 译文：我先走啦，回头聊
```

- ❶ 无错时显示「没问题」（润色照常给，供参考）
- 点 ❸ 上屏中文到目标 App 输入框（上屏后仍可在目标 App 里改）
- 点 ❷ 用润色版**替换键盘英文框内容**，供用户模仿重写或直接再译
- 译文基准：中文始终从**润色版**译出

### 翻译触发

- MVP：手动点「译」按钮
- 后置（非本期）：句界自动触发（检测 `.` `?` `!` 后停顿约 800ms 自动调用）
- 明确不做逐键实时翻译（LLM 延迟与成本不可行）

### 切换回中文

用系统原生键盘切换键切回原输入法，不做本键盘内的中文输入。

## 三、技术方案

### 基底：HeliBoard（fork）

- OpenBoard 的活跃 fork，Java，GPLv3，持续更新，上 F-Droid
- **只用其按键布局渲染与按键事件**，输出重定向到键盘自有 EditText
- 绕开基底自带的联想/候选/纠错机制（这是不从零造键盘的关键：光标、删字、换行 EditText 原生全有）
- HeliBoard 默认无联网权限；本项目需自行声明 INTERNET 权限（仅「译」调用使用）

### LLM 调用

- OpenAI 兼容接口直连 DeepSeek，Key 存手机本地（设置页录入）
- 参数：温度 0.3，json_mode，非流式
- 单次调用返回结构化三字段：

```json
{
  "corrections": [
    {"wrong": "should to go", "right": "should go", "note": "情态动词后接原形"}
  ],
  "polished": "I'm gonna head out now, ttyl",
  "translation": "我先走啦，回头聊"
}
```

- `corrections` 为空数组 = 无错
- LLM 异常/垃圾输出 → 降级：提示错误 + 支持重试，不阻塞输入（与主仓查词代理降级纪律同构）

### Prompt 要点（批改降噪是重点）

- 明确「口语聊天语境，只标真错，不推书面语」：gonna、wanna、缩写、省略主语均不算错
- corrections 只报告语法/用词/拼写硬错误，每条附中文简注
- polished 保持口语风格润色，不得改成书面腔
- translation 从润色版语义译出，自然口语中文

## 四、阶段划分

### 阶段一（MVP，本期交接范围）

1. fork HeliBoard，改包名，剥离非必要功能（按需最小化，能跑就行）
2. 键盘 UI：英文输入框 + 「译」按钮 + 三合一结果展示区
3. 按键输出重定向到自有 EditText
4. DeepSeek 直连调用 + 结构化解析 + 降级重试
5. 点译子上屏：译文→目标 App 输入框；润色→替换英文框
6. 设置页：API Key / Base URL / Model 三项配置
7. 学习留档（raw→polished 差值本地记录）：**本期做最小版**——本地 JSON 存最近 200 条（时间戳、原文、批改、润色、译文），不做界面，数据落盘即可，复盘界面后置

### 阶段二（后置，本期只记不算）

- 词汇联动：键盘定期从学习站拉取用户资产库词汇表（依赖 lykiehub.com 域名 + HTTPS + 一个简单词汇导出 API）
- 写作推荐：词汇表缓存本地，键盘英文框检测到学过的词干/同义意图时，候选区提示「学过 embrace，要用吗？」（纯本地匹配，零 LLM 调用）
- 每日佳句：服务器侧每日用 LLM 生成学词佳句缓存，键盘拉取展示
- 红线：**只做拉起式，不做推送**——佳句仅在打开键盘时候选区空闲位置展示，无通知无任务感
- 依赖顺序：阶段二开工前需学习站先完成域名+HTTPS+导出 API

## 五、验收标准（阶段一）

1. **构建**：Android Studio 打开可构建出 APK，sideload 安装后可在系统设置中启用为输入法
2. **双输入框**：任意 App（微信/QQ/备忘录）中拉起本键盘，英文框打字正常（含退格、空格、标点），目标 App 输入框无任何英文出现
3. **三合一**：输入含错句（如 `you should to go`）点「译」，三行结果齐全且批改正确；输入无错句显示「没问题」+ 润色 + 译文
4. **上屏**：点译文，中文出现在目标 App 输入框且可继续编辑；点润色，英文框内容被替换
5. **降噪**：`im gonna head out, ttyl` 不得被判错（口语纪律生效）
6. **降级**：断网/错误 Key 点「译」，得到中文错误提示 + 重试可恢复，输入不丢失
7. **留档**：每次调用后本地 JSON 可查到完整记录，上限 200 条滚动
8. **零静默**：不申请 INTERNET 以外的危险权限；无任何后台行为
