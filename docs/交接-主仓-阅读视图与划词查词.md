# 交接规格：阅读视图 + 划词查词（AI 入住第一步）

> 作者：顾问（按用户 2026-10-14 指令起草）｜状态：**已实现**——2026-10-14 顾问按用户「按规格执行」指令实现并验证完毕，未提交 git
> 背景与产品定位见 `docs/资产库定位-外置大脑.md` 备忘区「站内阅读视图」条目。本规格合并原阶段一（划词即录）与阶段二（BYOK 查词），一次交付核心闭环。

## 目标

用户在站内粘贴真题文章 → 阅读时划选生词/短语 → DeepSeek 自动整理「词头、词性、语境义、例句（原句+翻译）」→ **用户修改确认后**入库资产库。翻译功能同管道：划选长句直接给译文。

核心闭环一句话：**哪里不会点哪里，确认后成为自己的资产。**

## 决策点（作者 2026-10-14 已拍板）

| # | 决策点 | 拍板结果 |
|--|--|--|
| 1 | 查词触发方式 | **选中出气泡按钮，点击才调 API**（按推荐：防误选/双击烧 key） |
| 2 | 整句翻译 | **包含**；完整句**默认以句点（.）结尾**为一句（问号/叹号作句界兜底，见前端规格） |
| 3 | 已录词自动高亮 | **本期不做**（下一期单独做、单独验收） |

## 范围

**做**：文章导入（粘贴文本）、阅读渲染、划词气泡（查词/翻译）、查词卡片（可编辑→确认入库）、整句翻译、查询日志记录。

**不做**（后续阶段，见定位文档）：已录词高亮、锚点批注、AI 整理全部笔记入库、划词自由问答、其他题型（听力/完形）排版适配。

## 数据结构

新文件 `data/users/<user>/readings.json`（与 assets.json 同级，复用各用户目录的读写模式）：

```json
{
  "texts": [
    {
      "id": "rt_<rand>",
      "title": "2024-12 第一套 阅读1",
      "source": "四级真题202412第一套阅读1",
      "content": "段落文本，段落间以空行（\\n\\n）分隔",
      "created_at": "ISO时间"
    }
  ],
  "lookups": [
    {
      "id": "lk_<rand>",
      "text_id": "rt_xxx",
      "selection": "embrace",
      "sentence": "…整句…",
      "mode": "lookup|translate",
      "head": "embrace",
      "imported": false,
      "at": "ISO时间"
    }
  ]
}
```

- `source` 建文时填写一次，本篇所有查词卡片来源自动预填——解决重复输来源的痛点。
- `lookups` 本期**只记录不展示**，是阶段三「AI 全程见证（知道我问了什么、记了什么）」的数据地基；`imported` 在卡片提交成功后回写 true。

## 后端规格

### 路由（app.py，与 assets 路由同区、同 jsonify_user 风格）

| 路由 | 功能 |
|--|--|
| GET `/reading` | 文章列表页（标题/来源/创建时间，点开进入阅读，支持删除） |
| GET `/reading/<id>` | 阅读视图页 |
| POST `/api/reading/texts` | 新建：`{title, source, content}`，返回规范化后文本 |
| GET `/api/reading/texts` | 列表 |
| GET `/api/reading/texts/<id>` | 单篇详情 |
| POST `/api/reading/texts/<id>/delete` | 删除（lookups 里对应 text_id 一并清） |
| POST `/api/reading/lookup` | 查词/翻译代理（调 DeepSeek） |

### 文本规范化（入库 content 前）

与 `lykie/assets.py::_parse_examples` 同规则（一致性是硬要求）：单个换行 → 空格连接（PDF 复制的硬换行）；连续空行/多换行 → 段落分隔（`\n\n`）。段落内多余空格折叠为一个。

### 查词代理 `POST /api/reading/lookup`

请求：`{text_id, selection, sentence, mode}`（sentence 由前端从渲染文本提取，见前端节）。

**防幻觉关键设计：`sentence` 原样回填为 `example_en`，不经模型之手**——例句英文必须与文章一字不差（同句网络、来源锚定都依赖这一点），模型只产出释义和翻译。

`mode=lookup` 的 prompt（写死在规格，模型温度 0.3）：

```
你是英语词汇助手。下面给你一个英文句子和其中被选中的词或短语。
只依据这个句子的语境作答，不虚构、不补充句子之外的信息。输出严格 JSON：
{
  "head": "选中内容的词典词头原形，小写；若是短语则保持原样",
  "pos": "词性缩写，从 n./v./adj./adv./n.&v./prep./conj./phr. 中选最贴切的一个",
  "meaning": "该词在此句语境中的中文释义，简明，只给这一个义项",
  "example_zh": "整个句子的中文翻译"
}
句子：{sentence}
选中：{selection}
```

`mode=translate` 的 prompt：只要求输出 `{"example_zh": "整句中文翻译"}`。

实现要点：
- 复用 `lykie/llm.py::chat_completion(messages, temperature=0.3, json_mode=True)`，不新建客户端。
- JSON 解析失败 → 降级：从返回文本里正则提取首个 `{...}` 块再试一次；仍失败返回 `{ok:false, error:"模型返回异常，请手动填写"}`，HTTP 200（业务错误不走 5xx，前端统一处理）。
- `pos` 不在合法集合内 → 置 `other`，不报错（卡片上用户可改）。
- `head` 做与 record_vocab 相同的规范化（strip/小写）；`head` 与 `selection` 完全不同时仍按模型结果给（可能是原形还原，如 embraced→embrace），用户在卡片确认。
- 成功响应：`{ok:true, draft:{head, pos, meaning, example_en, example_zh}}`（`example_en`=请求里的 sentence）。
- 同时向 `lookups` 追加一条记录（mode=lookup 时含 head）。
- 超时/异常（Key 失效、断网）：捕获后返回 `{ok:false, error:"查询失败：<原因>，可手动填写"}`，**前端卡片照常打开、字段为空**，降级为普通手动录词——AI 不可用不阻塞录入。

### 算力与安全

- 复用 `.env` 的 `LYKIE_API_KEY/BASE_URL/MODEL`（业主自己的 Key，与 Lykie 对话同款先例），站点零新增成本。
- 防滥用：仅登录用户；单次单查，前端查询中禁用按钮（后端不做并发锁，个人站够用）。
- **备忘**：将来开放多用户时，此管道必须切 BYOK（用户自己的 Key），届时规格另出。

## 前端规格

### 新文件

`templates/reading.html`（列表页）、`templates/reading_view.html`（阅读页）、`static/reading.js`、`static/reading.css`。导航入口与「资产库」同级，命名「阅读」。静态资源版本号 bump。

### 文章导入（列表页「新建」）

表单：标题、来源（必填，一次填写全篇复用）、正文（大文本域，直接粘贴 PDF 复制的文本）。提交即后端规范化，前端展示规范化预览（段落效果）后保存。

### 阅读视图

- 段落渲染（`content.split("\n\n")` → `<p>`），行高与字号照顾长时间阅读，正文区最大宽度约 720px 居中。
- 页头常驻：标题、来源、返回列表。

### 划词交互（核心）

1. 在正文区 `mouseup` 时读取 `window.getSelection()`，非空且 anchor/focus 都在正文内 → 显示浮动气泡（定位于选区右下方，视口边缘自动翻转）。
2. 选区词数 ≤5（按空格切）→ 气泡按钮「查词」；>5 → 「翻译」。两按钮也可同时显示，主按钮按词数高亮。
3. 前端提取**整句**：从选区所在段落文本中，向两侧扩展至句界或段落边界。**句界规则（作者拍板）：默认以句点（.）结尾算完整一句；问号（?）/叹号（!）同样视为句界兜底**——防止疑问句内的选区越过问号吞进下一句。提取结果即为 `sentence`。缩写误切（U.S. 等）可接受——卡片里可改。
4. 点「查词」→ 气泡转为加载态（按钮禁用防连点）→ `POST /api/reading/lookup` → 打开**查词卡片**；失败也打开卡片（空字段+错误提示）。
5. 点「翻译」→ 同管道 → 气泡内直接展示译文（可复制），不入库、不开卡片。翻译不记 lookups？——记（mode=translate），见证数据完整。

### 查词卡片（确认步骤，防幻觉的最后关卡）

选中词旁边的浮动卡片，字段全部**可编辑**：

| 字段 | 预填来源 |
|--|--|
| 词头 | draft.head |
| 词性 | draft.pos（下拉，选项=POS_OPTIONS） |
| 语境义 | draft.meaning |
| 例句英文 | draft.example_en（=原句，只读展示+可点编辑） |
| 例句中文 | draft.example_zh |
| 来源 | 本文 source（只读） |

按钮：「存入资产库」「取消」。

提交 → `POST /api/assets/vocab`，载荷形状与现有录词表单完全一致（word/pos/meaning/examples(单条例句，`en||zh` 格式走现有解析)/source）→ **复用 record_vocab 全部现有逻辑**：一词一头合并、record_count+1、义项合并、双向例句同步、stub 升级，一行后端不用改。

成功后：卡片收起 + 轻提示（含「自动同步 N 条」如有）+ 对应 lookup 回写 `imported=true`；选中区可在正文里加一个轻量下划线样式（本期最简标记，不做 hover 弹层——那是「已录词高亮」期的活）。

### 失败降级

查询失败：卡片打开、字段空、顶部错误提示一行、来源照常预填——等于现场手动录词，不白来。

## 验收标准

1. 粘贴含 PDF 硬换行的真题文本 → 列表预览与阅读页段落渲染正常（无断行残留）
2. 划选 embrace（≤5 词）→ 气泡「查词」→ 卡片字段齐且**例句英文与原文一字不差**
3. 修改释义后提交 → 资产库词条内容与修改一致，来源=本文 source
4. 查已录词再提交 → record_count+1、义项合并；含其他已录词的例句触发双向同步（提示「自动同步 N 条」）
5. 划选整句 → 「翻译」→ 气泡展示译文
6. 临时改错 `.env` Key → 查词返回明确错误提示，卡片可手动填写并成功入库
7. 查询期间按钮禁用；快速重复划选不产生并发请求堆积（以最后一个为准即可）
8. `readings.json` 的 texts/lookups 结构与本规格一致；删除文章后 lookups 同步清理
9. 既有功能回归：`/assets` 录词、列表、删除不受影响；`node --check`、`py_compile` 通过

## 实施记录补遗（2026-10-14 下午：分段修复 + 阅读排版）

用户实测反馈：文本导入不分段（正文/题目混排成巨型段落）、阅读密集伤眼。本轮修复：

### 分段器升级（readings.py normalize_content 重写）

从例句管道规则（仅空行分段）升级为 **CET 感知分段器**，纯规则零模型，只插段落边界不动正文字符：

- 空行 → 分段（保留）
- 题号行（`46.` / `46)`，要求标点，防 `50 percent` 误判；`(?!\d)` 防小数 `3.5` 误判）→ 起新段，折行续文并入同段
- 选项行（`A)` `B.` … A-F）→ 各自起新段
- 题区标记（`Part IV` / `Section C` / `Passage One` / `Questions 46 to 50`，`Part of the problem` 这类正文开头不误判）→ 独立成段
- **段末短行启发**：行以 `.!?`（含后随引号）结尾且 < 62% 平均行长（阈值下限 28）→ 并入该段并结束（PDF 段落末行通常不满行）
- 幂等（normalize 两次结果不变）、CRLF/多空行容忍

### 导入实时预览

- 新增 `POST /api/reading/preview`：与 create 走同一 normalize_content，所见即最终阅读效果
- 列表页新建表单：正文输入 400ms 防抖调预览，渲染分段结果 + 段数统计；漏分段处用户在正文补空行兜底
- 预览请求带序号防旧响应

### 阅读排版（护眼）

- 正文 1.02rem→**1.125rem**，行高 1.9→**2.0**，段距 1.1em→**1.5em**，内边距加大
- **纸感底色**（仅阅读正文区，局部变量 `--rd-paper/--rd-ink/--rd-border`，不影响其他页面）：浅色米白 `#faf7f0` + 柔和墨色；深色暖褐 `#292620`——把对比度压到接近实体试卷
- 移动端（≤640px）字号/边距回落
- 静态资源 v=2（reading.css/reading.js，两模板同步 bump）

### 验证（8 case 全过）

PDF 折行合并/题目折行合并/选项独立/标记独立/词零丢失/三类误判防护（小数、Part of、无标点数字）/空行+CRLF+幂等/短行启发正确语义（末行并入并结束）/preview 端点与 create 一致/阅读页渲染 8 段。

既有 3 篇文章为旧分段数据，**不迁移**（按定稿）：在列表页删除后重新粘贴导入即可享受新分段。

## 实施记录补遗 2（2026-10-14 晚：侧栏题目 + 深色回退）

用户反馈：深色纸感不好看；正文含题目太长，题目放侧面随时呼出。拍板：方案 A（题目移出正文入侧栏），侧栏呼出时正文**平移不压缩**。

### 题目分离（lykie/readings.py::split_questions）

- 题目组 = 题号段 + 后续非正文段（选项/题干续句）；正文段判定：≥120 字符且非选项/标记/题号开头（**题号开头的段永远是题目**，防长题干被误判为正文——测试抓出的 bug）
- 孤立短段（短行启发拆出的题干续句）归入上一题
- 纯文章（无题号）questions 为空 → 侧栏与开关都不渲染
- 词零丢失（正文+题目=原文全部词，测试逐词核对）

### v7 五项优化（2026-10-15，用户反馈：方向正确，5 个小问题）

### v8 四项修正（2026-10-15，用户实测反馈）

1. **开合位置统一**：卡片位置独立持久化（localStorage `rd-qcard-pos`）。关卡片 → 卡片位置存档、球落在卡片左上角；开卡片 → 原路恢复上次位置（clamp 收敛），首次无存档时才用球上方居中兜底。位置不再漂移。
2. **单次出现标记**：查词记录新增 `para_index`（段序号）+ `occur_index`（段内第几次出现，0 起），查词请求携带（`positionOfSelection` 于 fetch 前计算：Range 前缀计数）；`markLookuped` 重写为按位置包裹**查词时的那一处**（`wrapOccurrence`：TreeWalker 收集文本节点 → splitText 包 span，跳过已标记节点）。旧记录无位置字段 → 刷新后不标记（可接受）。存词时 `.rd-saved` 直接升级 rd-mark-imported 类 + data-gloss，不再全文重标；题目区（卡片/全部）不做历史标记（每次重渲染，位置字段只对正文有效）。
3. **PDF 页脚过滤**：`normalize_content` 新增 `_FOOTER_RE`（`^\d{4}\s*年\s*\d{1,2}\s*月.{0,30}大学英语[四六]级考试.{0,30}真题.{0,20}$`），页脚行整行丢弃；正文含年份的正常句子不受影响（测试覆盖）。
4. **查词卡片可拖动 + 加载态**：卡片顶部新增 grip 手柄（⠿，pointer capture 拖动）；气泡查询中状态加 CSS 转圈动画（`is-loading` 类 + `rd-spin` keyframes），响应/异常/新查询时清除。

验证 6 case：页脚过滤（半角/全角括号）/年份正文不误伤/位置字段落库/非法值容错/marks 位置字段/v8 结构就位。资源 v=8。
