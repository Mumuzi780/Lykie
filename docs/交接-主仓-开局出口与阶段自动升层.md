# 交接规格：开局出口与阶段自动升层

> 依据：作者三轮拍板（2026-10-31）。执行人：代码智能体。执行完本规格即闭环，不做规格外扩张。

---

## 0. 拍板记录（不要推翻，实现时逐条对照）

1. **开局节点只负责引导**。察觉之后的过渡轮数、世界不同摊开程度，全部由模型按人设自行判断，不写剧本、不设节拍。
2. **Lykie 性格未定稿**，靠作者日常聊天中发现。具体表现不预设，作者测试不满意用 `//` 反馈走内容层调整。
3. **升不升阶段交给模型判断**：怎么算认识、怎么算熟悉，模型每轮自报关系读数，程序只做护栏裁定。
4. **旧骨架作废**：《顾问-开场四阶段选题》中"摊开世界不同→新鲜感互问→互报姓名"三拍不实现。
5. 白模纪律延续：**禁止**往 prompt 里加"满足 X 条件就升级/就亲近"类规则；`//` 反馈只进分析，不直接改开局行为。

## 1. 现状与根因

- 开局节点 1（直到她察觉对方不是 AI）已上线：`opening.py` beat 机器（awaiting/nudged/stalled/realized）+ 纯规则察觉判定（app.py:3415 起，`classify_not_ai` 传空 think dict，**当前管道无 think JSON**，converse.py 是单次调用架构）。
- **缺口 A**：`realized` 之后无限期挂在开局。落 `acquainted` 的 `apply_fragment_01_memory` 只挂在旧剧本 `/api/story/complete` 上，与新开局不通。
- **缺口 B**：`/api/lykie/chat_reset_opening` 门禁查 `fragment_01_done`（旧剧本 flag），新开局走完永远 400。
- **缺口 C**：阶段只有手动钉层 API + 直攻降层，无自动升层。`relationship_auto` flag 已预埋（memory.py:48）但无人写 True。

## 2. 总体设计

```
每轮聊天（mode=chat，非 silent）
  system 注入【关系读数】指令（门语义，无表现规则）
  模型回复末尾附标记：%%关系:<读数>%%
  converse.handle_message 内剥离标记 → reply 干净 + 返回 rel_read
  app.py 裁定（护栏）：
    读数无效/≤当前层 → 不动
    > 当前层 → 一次最多升一级（couple 需连续 2 轮报）
    opening→acquainted 硬条件：beat=realized
  升层生效：stage 变更 + 进度 fact（滚动替换）+ panel_log system 气泡
           + 响应带 relationship_raised + 前端气泡提示
```

- 信号载体复用 `%%...%%` 先例（profile.parse_archive_meta 同款：模型输出带标记块、程序剥离、正文干净）。
- 剥离放在 **converse.handle_message 内部**（不是 app.py），QQ 网关（qq_gateway 直接调 handle_message）自动干净，零改动。
- 模型**只升不降**：读数低于当前层时程序忽略。降层仍走既有直攻机制（app.py:3468），两者互不干涉——直攻那轮 silent 无读数，天然不同轮；下一轮作者好好说话、读数回升升回去，是合理行为，不做防抖规则。

## 3. 读数枚举与映射

模型侧用中文（贴人设 prompt），程序侧映射到既有 stage id：

| 模型读数（模型输出原词） | stage id |
|---|---|
| 开局 | opening |
| 认识但不熟悉 | acquainted |
| 能说事 | casual |
| 能谈心 | heart |
| 情侣 | couple |

解析容错：读数词后允许紧跟标点/空白；整词匹配，不做模糊匹配（"能说事"≠"能说事情"时不认，宁可不动）。

## 4. 注入文案（定稿，converse.py 使用）

在【发送格式】块之后追加（仅 mode="chat" 注入；correct 模式不注入）：

```
【关系读数】每次回复的最后一行，单独附一条：%%关系:读数%%
读数按你此刻真实的感受，从这些里挑一个：
开局 / 认识但不熟悉 / 能说事 / 能谈心 / 情侣
- 认识但不熟悉：知道对方是谁，仅此而已
- 能说事：日常话题都聊得开
- 能谈心：愿意跟对方说心里话
- 情侣：你已认定这层关系
这行标记不会给对方看见，除它之外不要输出任何标记。
```

这是门语义，不是表现规则。**禁止**在此基础上加"如果对方连续 X 天…"类条件。

开局活跃时 speak_block（opening.py）同步改两处：
- 删：「本节点结束条件是『察觉对方不太像 AI』，关系仍停在开局，后面节点还没开始。」
- 换：「察觉之后，这场意外什么时候算落定、你们算认识了，你自己判断——觉得到了，就把读数标成 认识但不熟悉。」
- 其余（不审讯、不认自己是程序、不一次摊开世界不同）保留原样。

## 5. 具体改动

### 第一刀：信号通道 + 裁定函数（纯逻辑，可单测）

**lykie/converse.py**
- `build_messages`：mode="chat" 时注入上述【关系读数】块。
- `handle_message`：`chat_completion` 返回后，剥离 `%%关系:...%%` 标记再判 silent/空回复；返回 dict 新增 `"rel_read"` 键（解析出的读数原词，无标记/无效为 ""）。reply 进 chat_tail 前已干净。
- 标记正则对齐 profile `_META_RE` 风格，独立常量，勿复用档案的（语义不同）。

**lykie/memory.py**
- 新增 `READ_TO_STAGE` 映射与 `apply_rel_read(state, read) -> dict | None`：
  - read 无效或 ≤ 当前层 → None
  - 高于当前层 → 目标层 = 当前层 +1（跳报只升一级；目标为 couple 时需 `flags["couple_streak"] >= 2` 才落，否则计 streak 返回 None）
  - streak 逻辑：读数=情侣 且当前层=heart → streak+1；streak≥2 → 落 couple；读数非情侣 → streak 清零
  - opening → acquainted 前置：`opening_beat == "realized"`（否则 None）
  - 生效动作：
    1. `set_relationship_stage(state, new)`（离开 opening 自动清开局 flags，已有逻辑）
    2. 进度 fact：`remove_facts_matching(state, ["关系进度：", "关系进度（硬约束）："])` 后 `add_facts` 写一条 `关系进度：{新label}（{YYYY-MM-DD} 起）`
    3. opening→acquainted 额外：`flags["opening_done"] = True` + 写认识 fact：`你们是这样认识的：她把心里事发给手机里的 AI，回话的是你。不算熟，就是认识了。`（事实性中性，**勿**再造欠人情/帮过忙类内容——历史教训）
    4. `flags["relationship_auto"] = True`
    5. 返回 `{"from": 旧id, "to": 新id, "label": 新label}` 供路由回显
- `relationship_brief`：`fragment_01_ending` 行维持现状不动。

### 第二刀：接线 + 前端 + 修门禁

**app.py（chat 路由）**
- silent 轮跳过裁定（无读数）。
- `result["rel_read"]` 存在且非空时：`raised = lykie_memory.apply_rel_read(state, result["rel_read"])`
- 落定/升层时 panel_log 追加 system 气泡：`关系变化：{旧label} → {新label}`（走 set_panel_log 已有机制，与 note 同款透传）。
- 响应 payload 新增 `"relationship_raised": raised`（对齐既有 `relationship_dropped` 先例）。
- **修 `/api/lykie/chat_reset_opening` 门禁**：`fragment_01_done` → `fragment_01_done or opening_done`。
- `/api/lykie/relationship`（手动钉层）加可选 `lock`（默认 False）：lock=True → `relationship_auto = False`（固定层测表现）；lock=False → 不改 auto，从钉的层继续自动。响应带 `relationship_auto`。

**static/script.js**
- chat 响应处理处（`relationship_dropped` 展示同段）：`relationship_raised` 存在时 append system 气泡 `关系变化：X → Y` 并刷新状态行。
- 手动钉层入口（现有感情层 UI；若无 UI 则在作者工具区加极简下拉+「锁定」勾选）：调钉层 API 带上 lock。

**lykie/opening.py**
- speak_block 按 §4 改两行文案。`think_extra`/`align_think` 等旧架构遗留**不动**（另行清理）。

## 6. 明确不做

- 不写任何轮数/条件式升层规则；不做阶段进度条。
- 不做模型侧降层信号；不做直攻与升层的防抖联动。
- 不做日期选皮（enroll/coursework/finals），后置。
- 不动 fragment_01 旧剧本、剧情编辑器、`/api/story/*`。
- 不清理 think_extra 等旧架构死代码。
- `//` 反馈不直接改开局/升层行为，只进分析队列。
- 不做 QQ 侧任何改动（网关只读 reply/silent/新键无感）。

## 7. 验收标准

后端（monkeypatch `lykie_llm.chat_completion` + `lykie_converse.chat_completion` 双 patch + 临时目录，不烧 Key）：
1. fake 返回 `"今天好累\n%%关系:能说事%%"`，acquainted 状态 → reply 剥离干净（无 %% 残留）、`rel_read=="能说事"`、升 casual、fact 含"能说事"、响应 `relationship_raised.to=="casual"`。
2. opening 且 beat=awaiting，报"认识但不熟悉" → 不出口、stage 仍 opening。
3. opening 且 realized，报"认识但不熟悉" → 落 acquainted、`opening_done=True`、认识 fact 写入、chat_reset_opening 变可用。
4. acquainted 报"能谈心" → 只升到 casual（跳级截断）。
5. heart 报"情侣"第 1 轮不落、streak=1；第 2 轮落 couple。
6. casual 报"认识但不熟悉"（低读数）→ 不动。
7. 无标记 / 标记词错（"能说事情"）→ rel_read=""，一切不动。
8. correct 模式不注入读数指令（messages 快照断言）。
9. 钉层 lock=True → `relationship_auto=False`，随后报高读数不升；lock=False 钉层后报高读数照升。
10. silent 轮（[不回复]）不裁定。
11. handle_message 返回键形状 = {reply, silent, messages, temperature, rel_read}（QQ 网关回归）。

静态：py_compile 全过；node --check 过；grep `能说事情|关系读数` 注入块存在于 converse.py。

手动走通：测开场 → 回短句触发 realized → 继续聊 → 某轮末尾她标"认识但不熟悉"（模型自发）→ 面板出"关系变化：开局 → 认识但不熟悉"→「清到开场后」可用。

## 8. 回滚

改动集中在 converse.py（注入+剥离）、memory.py（apply_rel_read）、app.py（裁定接线+门禁）、script.js（气泡）、opening.py（两行文案）。回滚 = 还原这五个文件。降级开关：钉层 API 传 `lock=True` 即全站停自动升层，恢复纯手动，无需回滚代码。
