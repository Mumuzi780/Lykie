# Lykie 产品定位与方向

> 本文是产品战略的权威记录。讨论功能、进题、背题、商业化或推广时，以本文为准；细节方案可迭代，本文中的定位与边界不要轻易改写。

最后整理：2026-09-04

---

## 一句话

**学习站是免费引子；Lykie（角色/陪伴）是绝对特色与长期资产；赚钱放在用户认了 Lykie 之后的正式作品（如独立游戏），不在当前学习站上挤利润。**

---

## 产品是什么 / 不是什么

| 是 | 不是 |
|----|------|
| 过考试工具：自定义题库 + 尽量无脑记住考点 | 专业教培 / 学习指导站 |
| 以大学生等用户**自己导入的题**为主 | 靠你方专业团队选题、运营大型共享题库来竞争 |
| 工具站：格式化、抽背、陪伴 | 卖课、卖题、卖会员驱动的学习社区 |
| Lykie 可做成独立向的陪伴/剧情体验（类比「彼方的她 Aliya」一类） | 把 Lykie 只当成学习页的装饰 chatbot |

核心目标：**无脑过考试**，不是「真正学会」。在有专业内容团队之前，**共享题库不是重点需求**。

---

## 商业与增长（最终形态）

### 漏斗

1. **获客**：抖音等——自己发，并尽量联系有影响力的博主；话术偏「意外发现宝藏站」「学习还能认识有趣的新朋友」「一起学」「完全免费」等，突出 **Lykie**。
2. **留存引子**：学习功能必须**真的有用**，且**完全免费**，把人留在站上、认识 Lykie。
3. **粘性**：用户认可 Lykie 的人设与陪伴后，粘性主要落在角色上。
4. **变现**：正式版盈利项目（独立游戏或其它形态）发布时，这批用户更容易买单。

### 对当前站的硬约束

- **学习功能不收费**，不做「用付费解锁背题」一类设计。
- **不把识图/大模型算力做成站点固定成本**（站点大概率难靠学习功能盈利，不能长期自己贴钱买识图 API）。
- 特色与预算优先：**Lykie** + 少量真正降低学习摩擦的能力；不把精力用在和专业刷题 App 拼题库、拼教法。

## 学习侧方向（已讨论结论）

### 进题

- 主路径仍是用户导入（老师发的 Word/题库等，定制感强、网上不流通）——与最初大学生定位一致。
- 向流行大考（如教资）扩展时：题多在其它 App 里；**不研究各 App 专有导出**，要跨软件统一的套路。
- **截图是统一、最方便的进题姿势**；冷启动不要求截一百张——**先 3～5 张体验**，认可后再按天补图。
- 工程上进题优化重点是**批量图片相关流程**；但识图算力不归站点买单。

### 识图 / 结构化（成本）

- **站点垫付云端识图 API：不可行。**
- 后续 Lykie/学习相关的模型能力，方向是 **用户自备 API Key（BYOK）**。
- 在 BYOK 普及前，最现实默认档：**用户到流行 AI 网页端完成识图**，站点提供固定提示词与格式 → 用户把结果**粘贴回 Lykie** 入库。站点做工具管道，不做算力中心。
- 本机重型 OCR 不适合当前小规格服务器（约 2 核 2G），也不作为默认方案。

### 无痛 / 无脑背简答（大方向，细则未定死）

- 大方向：像现有抽卡背题一样**无脑**——系统喂下一张，用户轻操作，间隔与难度由系统扛；目标是过考得分点，不是背长文。
- **不照搬**市面「背简答」App 的整套方案（红字教学、口诀主路径、选字/手填检测切换、默记 vs 检测双模式等）作为产品抄袭对象；可参考其「降低一次背整段的痛苦」，但体验要落在「背题机」而非「又一个学习检测 App」。
- 拆题粒度、线索消退、再认→单点→整题等**具体机制必须本人试用后才能定**；未确认前不要当成已定实现规格去开发。
- 短简答训练的实测感受、分题对比与后续「一题一题沉淀可复用工具」流程，见同目录 [`简答训练-测试笔记.md`](简答训练-测试笔记.md)。
- 在机制摸索期，可先做进题管道；背题系统与负责人**一点一点协调**，不一次锁死。

## Lykie 角色侧

- Lykie 是绝对特色，也是推广与长期变现的锚点。
- 学习站负责「把人带来并证明好用」；角色负责「让人留下来、日后为正式作品买单」。
- 角色与剧情的设定细节见同目录其它文档（如 `角色与剧情构想.md`）；**商业定位以本文为准**，勿写成「付费学习产品」。

---

## 决策时快速对照

做新功能前问：

1. 是否让学习更好用、且仍完全免费？  
2. 是否加强 Lykie 粘性或可传播人设？  
3. 是否让站点背上不可持续的 API/内容成本？→ 应避免。  
4. 是否在和专业教培拼选题/带学？→ 不是我们的赛道。  
5. 简答记忆细则是否已被负责人试用确认？→ 未确认则只讨论或小步试，不整锅实现。
